# 12-3 토큰 바인딩: 훔친 토큰이 다른 곳에서 안 되게
⏱ 약 9분 · 고칠 파일 자바 2개(`PartnerScopeInterceptor`·`DaonPartnerTokenController`) + secure-kit 새 부품 `PartnerClientCert` + 설정 3개(`infra/compose.a09.yml`·`infra/gateway/nginx.conf`·새 `infra/openbao/partner-pki.sh`) · 아키텍처 A9(mTLS) · 방어 스위치 `token-binding`

지금 파트너 토큰은 **무기명**입니다. 누가 내밀든 통합니다. 토큰을 클라이언트 인증서에 묶으면 토큰만으로는 안 되고 인증서의 개인키도 있어야 합니다.

> 안전 원칙: 「훔친 토큰」 장면은 같은 PC 안에서 **다른 클라이언트 설정**(인증서 없이, 다른 파트너의 인증서로)이 같은 토큰을 내미는 수준입니다. 토큰을 빼내는 방법은 다루지 않습니다.

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=12-3
   make replay T=33 PART=reuse   # 인증서 없이·다른 인증서로도 200 [레드]
   make check L=12-3
   ```
2. **랩 내부 CA를 켭니다(✏️ 새 `infra/openbao/partner-pki.sh`, `compose.a09.yml`의 `partner-pki`).** OpenBao PKI 엔진 `pki-partner/`가 CA(10년)·게이트웨이 서버 인증서(127.0.0.1)·파트너 클라이언트 인증서 셋(30일)을 만듭니다. 5-5는 그림 설명 수업이라 CA를 이 수업에서 처음 켭니다. 개인키는 볼륨에만 있고 저장소에 넣지 않습니다. 게이트웨이에는 자기 인증서와 CA만 붙입니다.
3. **파트너 입구를 mTLS로(✏️ `infra/gateway/nginx.conf`).** `listen 8087 ssl` + `ssl_verify_client optional` + `ssl_client_certificate`. 확인한 인증서(`$ssl_client_verify = SUCCESS`)만 `X-Daon-Client-Cert`(URL 인코딩 PEM)로 넘기고, **밖에서 온 같은 이름 헤더는 늘 덮어씁니다**(빈 값 = 지움).
4. **발급 때 묶기(✏️ `DaonPartnerTokenController`).** 인증서 주인(CN)이 `client_id`와 같아야 발급. 인증서 지문을 `cnf: {"x5t#S256": …}`에 넣습니다(RFC 8705).
5. **요청 때 비교(✏️ `PartnerScopeInterceptor`, 새 `PartnerClientCert`).** 토큰의 `cnf` = 이 요청 인증서의 SHA-256 지문인지 상수 시간 비교. 다르거나 없으면 401 + `token.denied.binding_mismatch`. 헤더는 파트너 입구(소켓 주소 = 게이트웨이)에서 온 요청에서만 읽습니다.
6. **확인합니다.**
   ```bash
   make up STACK=spring          # partner-pki가 한 번 돌고 게이트웨이가 https로 뜬다
   make partner-certs            # 파트너 인증서를 .daon/partner-pki/로(파트너 앱 스텁·시험이 씀)
   make replay T=33 PART=reuse   # 인증서 없이 401 · 다른 인증서 401 [그린]
   make check L=12-3             # 6개(정상 1개: 자기 인증서를 쓰는 파트너 앱)
   make logs S=mall-portal | grep binding_mismatch
   ```
7. **DPoP는 그림으로.** 클라이언트가 요청마다 개인키로 짧은 증명(메서드·주소·시각·일회용 ID·토큰 해시)을 서명하고, 서버는 증명의 공개키 지문이 토큰의 지문과 같은지 봅니다. 같은 일을 앱 계층에서 합니다(랩에서는 구현하지 않음).
8. **스위치.** `make switch K=token-binding V=off` → `make replay T=33 PART=reuse` 레드 → `V=on`.

## 막힐 때
- 게이트웨이가 밖에서 온 지문 헤더를 지우지 않으면 공격자가 그 헤더를 직접 넣어 우회합니다. `proxy_set_header`가 핵심입니다(시험 「꾸민 헤더」).
- 인증서 만료가 토큰 수명보다 짧으면 갱신이 꼬입니다. 인증서는 길게(랩 30일, 7일 남으면 다음 `make up` 때 새로), 토큰은 짧게(15분).
- `ssl_verify_client on`으로 두면 인증서 없는 요청을 nginx가 400으로 끊어 앱 이벤트가 남지 않습니다. 이 랩은 `optional` + 앱 401로 「누구의 토큰이 어디서 쓰였나」를 남깁니다.
- `partner-pki`가 실패하면 게이트웨이가 뜨지 않습니다(입구 셋이 함께 멈춤). `make logs S=partner-pki`.
- Express: `diffs/s12-03/express.diff`는 같은 지문 비교를 `kit.partnerScope(scope, { bind: true })` 옵션 하나로 켭니다.

## 남는 이벤트
`token.denied.binding_mismatch`(WARN). 정상 상황에서는 나오지 않으므로 한 번이라도 경보(P1), 같은 파트너 토큰 즉시 폐기 후보(12-4).
