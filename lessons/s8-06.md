# 8-6 지울 수 없는 로그: 해시 체인과 별도 보관
⏱ 약 7분 · 고칠 파일 자바 1개 + 새 파일 1개 · 아키텍처 A5 그대로(머리 해시는 Loki 사본) · 방어 스위치 `audit-chain`

감사 로그는 감사받는 사람이 지울 수 없어야 합니다. 이 수업은 「지우면 들키게」(해시 체인)와 「머리 해시를 앱이 닿지 못하는 곳에」를 만듭니다. 「지우지 못하게」(객체 잠금)는 14-2에서 합니다.

> 안전 원칙: 재연(방어 확인)은 이 랩 안의 감사 로그 파일 한 줄을 지우는 수준이고 우회 기법은 없습니다. 끝나면 파일을 원래대로 되돌립니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=8-6
   make replay T=20x       # 관리자 조회 3번 → 가운데 줄(대량 조회)을 지움 → 파일은 멀쩡해 보이고 아무도 모른다 [레드]
   make audit-verify       # 「줄에 체인 정보가 없습니다」
   make check L=8-6
   ```
   (`T=20x`는 새 T 번호가 아닌 방어 확인입니다. 점수판에는 세지 않습니다.)
2. **체인으로 묶습니다(✏️ `AuditLog.java`, 새 파일 `AuditChain.java`).** 줄마다 `seq`(일련번호)·`prev`(앞 줄의 hash)·`hash`(이 줄 내용 + prev의 SHA-256). 해시 입력은 `hash`를 뺀 줄을 **키 이름 순으로 정렬한 JSON**(공백 없음)입니다. 같은 내용이면 같은 해시가 나와야 `make audit-verify`(파이썬)가 다시 계산할 수 있습니다. 앱이 다시 떠도 파일의 마지막 줄에서 이어 갑니다. 사유 칸은 사람이 적는 글자라 해시를 만들기 전에 먼저 가립니다(8-5 변환기가 나중에 바꾸면 해시가 어긋남).
3. **머리 해시를 따로 둡니다(설정 변화 없음).** 감사 로그는 8-4부터 수집기가 Loki로 보냅니다. Loki는 앱 망에 없고(앱 자격증명으로는 닿지도 못함) 삭제 API를 꺼 두었습니다. `make audit-verify`는 파일의 체인을 처음부터 다시 계산하고, Loki 사본에 「파일 마지막 줄의 다음 줄」이 있는지 봅니다. 있으면 끝 줄이 지워진 것입니다.
4. **⑤ 탐지.** 체인이 끊기거나 머리 해시가 맞지 않으면 `make audit-verify`가 종료 코드 1로 끝나고 도구 이벤트 `audit.chain.broken`(WARN, target `audit:mall-admin#seq=<번호>`)을 남깁니다. 표에서 「한 번이라도, 즉시(P1)」이라 `make alert-rules`가 만든 규칙으로 메일이 옵니다.
5. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=20x       # 「seq=N에서 앞 줄 해시 불일치」 [그린]
   make audit-verify       # 되돌린 뒤에는 통과(머리 해시 확인 포함)
   make check L=8-6        # 6개 통과(앱 컨테이너에서 Loki에 닿지 않는지 보는 정상 시험 포함)
   ```
6. **스위치.** `make switch K=audit-chain V=off` → 새 줄에 체인이 없음 → `V=on`이면 seq=1부터 새 체인이 시작합니다(`make audit-verify`가 「새 체인 시작」으로 알려 줌).

## 막힐 때
- JSON 키 순서가 바뀌면 같은 내용인데 해시가 달라집니다. 정렬된 직렬화(`ORDER_MAP_ENTRIES_BY_KEYS` + `TreeMap`)를 씁니다.
- 앱이 여러 개(인스턴스 둘)면 체인이 두 갈래가 됩니다. 운영에서는 인스턴스별 체인이나 중앙 기록 서비스가 필요합니다.
- 해시 체인은 「지우지 못하게」 하지 않습니다. 「지우면 들키게」 할 뿐입니다. 지우지 못하게 하는 것은 별도 저장소의 잠금입니다(14-2 MinIO 객체 잠금).
- 줄을 지운 직후 몇 초 안(수집기가 읽기 전)에 끝 줄을 지우면 Loki 사본도 없습니다. 수집 지연을 짧게, 운영에서는 앱이 직접 쓰기 전용 저장소로도 보냅니다.
- Express: `diffs/s8-06/express.diff`는 8-3의 `audit.ts`에 같은 `seq`·`prev`·`hash`를 넣습니다. 같은 확인 도구로 검사할 수 있습니다.
