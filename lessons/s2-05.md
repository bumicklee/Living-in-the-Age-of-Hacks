# 2-5 이미지 URL 가져오기가 내부망을 연다(SSRF)
⏱ 약 15분 · 고칠 파일 2개(코드 1 + 아키텍처 1줄) · 바뀌는 줄 약 90줄 · 아키텍처 A0 → A2

상품 등록 화면에 「이미지 URL로 가져오기」가 있습니다([교육용 추가]). 직원이 공급사 이미지 주소를 넣으면 관리자 앱이 대신 받아 미리 보기로 돌려줍니다(`GET /product/image/fetch?url=…`). 이 앱은 랩의 「인터넷」으로 바로 나가고, 받은 주소가 어디인지 확인하지 않습니다.

| 이름 | 무엇 |
|---|---|
| `img.partner-cdn.example` | 랩 안의 「인터넷」에 있는 가짜 이미지 공급사(203.0.113.20, 문서용 주소) |
| `127.0.0.1:8095/ops/config` | 관리자 앱 자신의 운영 도구. 설정 값(관리자 토큰 서명값 포함)을 돌려준다(2-6) |
| `mall-portal:8085` | 같은 망의 고객 앱 |

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=2-5
   make replay T=04
   make check L=2-5
   ```
   상품 담당 직원 `staff_goods`가 이미지 주소 대신 `http://127.0.0.1:8095/ops/config`를 넣으면 운영 도구의 설정 값이 미리 보기로 돌아옵니다. 그중 `jwt.secret`은 관리자 토큰을 만드는 서명값입니다.
2. **코드에서 막습니다.** `spring/mall-admin/.../daon/DaonImageFetcher.java`의 ✏️ 2-5 표시. 부르기 전에 다섯 가지를 확인합니다.
   1. 스킴은 `http`·`https`만 받습니다(`file:`, `jar:` 거부).
   2. 이름을 해석해 내부 주소면 거부합니다(루프백·사설·링크 로컬·CGNAT·IPv6 내부).
      ```java
      for (InetAddress a : InetAddress.getAllByName(uri.getHost())) {
          if (isInternal(a)) throw blocked("egress.denied.internal_address", url, "내부 주소로는 요청하지 않습니다");
      }
      ```
   3. 이그레스 프록시(`daon.egress.proxy`)가 설정되지 않았으면 나가지 않습니다. 실패하면 막습니다.
   4. 리다이렉트는 따라가지 않습니다(`setInstanceFollowRedirects(false)`). 검사한 주소와 실제로 가는 주소가 달라지기 때문입니다(11-1에서 자세히).
   5. 응답이 `image/*`가 아니면 돌려주지 않습니다.
3. **아키텍처 A2를 켭니다.** `infra/arch.txt` 맨 아래에 한 줄을 넣습니다.
   ```text
   a02
   ```
   다음 `make check` 때 `infra/compose.a02.yml`이 함께 켜집니다.
   - `egress`(Squid 프록시)가 생기고, 관리자 앱은 랩의 「인터넷」에서 빠집니다. 밖으로 나가는 길은 프록시 하나입니다.
   - 프록시 규칙은 `infra/egress/squid.conf`에 있습니다. 허용한 이름(`img.partner-cdn.example`)만 통과시키고, 내부 주소는 거부하고, 나머지는 기본 거부합니다.
   - 코드 검사와 프록시는 같은 일을 두 번 합니다. 코드 검사를 빠뜨린 다른 기능이 생겨도 프록시에서 한 번 더 막힙니다.
4. **⑤ 탐지: 막을 때마다 남깁니다.** `blocked(...)`가 예외를 만들기 전에 보안 이벤트를 남깁니다.
   ```java
   SecurityEventLogger.denied(event, "2-5")
           .target("host:" + hostOf(url))
           .reason(reason)
           .log();
   ```
   - 주소 전체가 아니라 호스트 이름만 남깁니다. 경로·쿼리에는 값이 섞일 수 있습니다.
   - 프록시 쪽 흔적도 봅니다: `make logs S=egress | grep TCP_DENIED`.
5. **확인합니다.**
   ```bash
   make check L=2-5      # 처음엔 egress 이미지를 받느라 조금 더 걸립니다
   make replay T=04      # [그린] 막힘
   make logs S=mall-admin | grep egress.denied
   ```
   공급사 이미지(`http://img.partner-cdn.example/daon-sample.png`)를 가져오는 정상 요청 시험도 그린이어야 합니다. 관리자 앱이 프록시 없이 밖에 닿는지, 프록시가 내부 주소를 거부하는지도 시험이 컨테이너 안에서 확인합니다.

## 한계
A2의 `daon` 망은 아직 보통 도커 브리지라 진짜 인터넷으로는 나갈 수 있습니다. 앱 컨테이너가 프록시 말고는 나갈 수 없게 하는 망 분리는 A1(6-4)에서 합니다.

## Express라면
`diffs/s2-05/express.diff`. EverShop 원본의 이미지 가져오기(`lib/util/secureFetch.ts`)는 이미 호스트 허용 목록으로 거르고 리다이렉트 단계마다 다시 검사합니다. diff는 보안 이벤트와 이그레스 프록시 경로만 더합니다.

## 막히면
- `make solution L=2-5` → 내 코드와 정답의 차이(`infra/arch.txt` 포함)
- `make apply-solution L=2-5` → 정답으로 덮어쓰기(내 파일은 `.daon/backup/`에 남습니다)

## 기억할 한 줄
서버가 대신 부르는 주소는 코드에서 한 번, 나가는 길(프록시)에서 한 번 더 막는다.
