# 8-2 감사 로그 설계: 누가, 무엇을, 얼마나
⏱ 약 8분 · 새 파일 1개(`docs/audit-schema.yaml`) · 아키텍처 변화 없음 · 설계 수업(코드는 8-3)

SECURITY 로그는 거부와 의심만 남깁니다. 정상 계정으로 하는 대량 조회는 거부되지 않으니 SECURITY 로그에 한 줄도 남지 않습니다. 이 수업은 개인정보가 나가는 **정상 조회**를 남길 감사 로그(AUDIT)의 모양을 정합니다.

## 따라 하기
1. **지금 무엇이 남는지 봅니다.**
   ```bash
   make goto L=8-2
   make peek W=list                         # 관리자 회원 목록(가짜 회원 alice·bob만 보임)
   make logs S=mall-admin | grep SECURITY   # 아무 줄도 없다: 정상 조회는 거부가 아니다
   make peek W=order A=9001                 # 관리자 주문 상세
   make logs S=mall-admin | grep WebLogAspect | tail -n 1   # 대신 요청·응답 전체가 INFO로(F35, 화면에서는 값을 가림)
   make check L=8-2                         # 설계 파일이 없어 레드
   ```
   「기록이 없다」가 아니라 「쓸 수 없는 기록만 있다」입니다. 누가 몇 명을 왜 봤는지는 없고, 응답 속 회원 정보가 로그에 복사됩니다.
2. **설계 파일을 씁니다(✏️ 새 파일 `docs/audit-schema.yaml`).**
   - 필수 필드 8개: `ts`·`trace_id`·`actor`(`admin:<계정>`)·`action`·`target`(종류와 ID, 또는 페이지 번호)·`count`(**돌려준** 건수)·`reason`(요청 헤더 `X-Access-Reason`, 상담 번호 등)·`result`(`ok`·`denied`·`error`)
   - 넣지 않는 것: 이름·전화·주소·이메일 원문, 토큰·비밀번호, 요청 본문, 응답 본문
   - 관리자 조회 넷의 `action`: `/daon/customer/list` → `customer.list`, `/order/list` → `order.list`, `/order/{id}` → `order.detail`, `/returnApply/list` → `return.list`
   - 대량 조회 기준 `bulk_threshold: 30`(시드 회원 40명으로 보이게 정한 랩 값, 운영은 업무량에 맞춤)
   - Express 대응표: EverShop 관리자 GraphQL `customers`·`customer(id)`·`orders` → 같은 `action` 이름
3. **확인합니다.**
   ```bash
   make check L=8-2      # 4개 통과(필수 필드·action 이름·넣지 않는 것·Express 대응표)
   ```

## 설계 메모
- 무엇을 남기나: 개인정보가 나가는 조회는 모두, 상품 목록처럼 개인정보가 없는 조회는 남기지 않습니다(양이 많으면 필요한 줄이 묻힙니다).
- 어디에 두나: 앱 로그와 다른 로거(`AUDIT`)·다른 파일. 8-4부터 Loki의 다른 스트림. 앱을 다루는 사람이 감사 로그를 지울 수 없어야 한다는 요구는 적어 두고, 막기는 8-6에서 합니다.
- `reason`: 목록은 선택, 내보내기는 필수로 나누면 업무가 막히지 않습니다.
- 8-4에서 이 필드로 만들 경보 셋을 미리 적습니다: 계정별 10분 누적 건수, 사유 없는 내보내기, 업무 시간 밖 대량 조회.

## 막힐 때
- `count`에 페이지 크기나 전체 건수(`total`)를 적는 실수가 많습니다. 실제로 돌려준 건수입니다.
- 「응답 전체를 남기면 더 자세하지 않나요?」: 로그가 개인정보 사본이 되고, 그 로그가 또 유출 경로가 됩니다(8-5).
