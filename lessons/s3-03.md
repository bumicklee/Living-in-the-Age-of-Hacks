# 3-3 정렬·검색 조건 같은 동적 쿼리를 안전하게
⏱ 약 9분 · 고칠 파일 3개(서비스·DAO·XML) · 바뀌는 줄 약 40줄(정답의 스위치 갈래 포함)

3-2에서 남겨 둔 정렬 줄 `order by ${sort}`를 고칩니다. 컬럼 이름·정렬 방향은 문장의 뼈대라 바인딩할 수 없습니다. 지금 검색 서비스는 화면이 보내는 정렬 이름(`new`·`price_asc`·`price_desc`·`sale`)을 정렬 표현으로 바꾸고, **목록에 없는 값은 「고급 정렬」이라며 받은 그대로** 넘깁니다([교육용 추가]).

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=3-3
   make replay T=06
   make check L=3-3
   ```
   재연은 정렬 값만 바꿉니다.
   - 화면에 없는 컬럼(재고 `stock`)으로 정렬하면 `HTTP 200`이고, 오름·내림 결과가 정확히 뒤집힙니다. 재고 수는 응답에 없지만 순서로 크고 작음이 드러납니다(재고 많은 순 앞 5개 221, 202, 220, 207, 227).
   - 컬럼 이름이 아닌 값이면 3-2와 같은 SQL 문법 오류 문구가 돌아옵니다(`HTTP 200`, 본문 `code=500`).
2. **바인딩을 먼저 해 봅니다(중간 장면).** XML의 `order by ${sort}`를 `order by #{sort}`로 바꾸고 `make check L=3-3`을 돌리면 정상 정렬 시험이 레드가 됩니다. 정렬 값이 `'price asc'`라는 문자열 상수가 되어 정렬이 걸리지 않습니다. 확인했으면 되돌립니다.
3. **허용 목록으로 바꿉니다.** `spring/mall-portal/.../service/impl/DaonProductSearchServiceImpl.java`의 ✏️ 3-3 표시.
   ```java
   String orderBy = SORTS.get(sort == null || sort.isBlank() ? "new" : sort);
   if (orderBy == null) {
       rejectSort();   // 400 + 탐지 로그
   }
   ```
   - `rejectSort()`는 이벤트를 남기고 `IllegalArgumentException`을 던집니다. 컨트롤러가 `HTTP 400` + 본문 `code=400`으로 바꿉니다.
   - 방향(`asc`·`desc`)도 따로 받지 않고 매핑 값에 넣습니다.
   - 정규식(`^[a-z_ ]+$`)으로 모양만 보면 `stock desc`도 통과합니다. 모양 검사가 아니라 목록 매핑입니다.
4. **매퍼 이름도 상수답게.** XML은 `order by ${orderByClause}`, DAO 매개변수는 `@Param("orderByClause")`. 들어오는 값이 서버 상수뿐이라 원본 생성 매퍼와 같은 처지가 되고, 3-2의 검색 스크립트도 「상수」로 봅니다(`결과: 입력 경로 ${ 없음`).
5. **⑤ 탐지.** 400을 돌려주기 직전에 남깁니다. 받은 정렬 값은 넣지 않습니다(로그 위조·개인정보 섞임 방지).
   ```java
   SecurityEventLogger.denied("input.rejected.sort_field", "3-3")
           .target("path:/daon/product/search")
           .reason("허용하지 않은 정렬 값")
           .log();
   ```
   로그인 없이 부르는 검색이라 `actor`는 `anonymous`입니다. 지금 `count`는 같은 event·actor 기준이라 익명 요청은 한 묶음으로 셉니다(출처별로 보려면 `ip`로 묶습니다, 8장).
6. **확인합니다.**
   ```bash
   make check L=3-3
   make replay T=06      # [그린] 검색어·정렬 네 경우 모두 막힘
   make score            # T06 그린
   make logs S=mall-portal | grep input.rejected.sort_field
   ```
   정상 정렬 네 가지(신상품·가격 오름·가격 내림·판매량) 순서는 고치기 전과 같아야 합니다.

## 원본이 잘한 것
원본 상품 검색(`PmsPortalProductServiceImpl.java` 60~69행)은 정렬을 숫자 1~4로 받고 코드 안에서 컬럼 이름을 고릅니다. `setOrderByClause`에 들어가는 값은 모두 상수입니다.

## Express라면
EverShop 상품 목록 정렬도 이미 허용 목록입니다: `express/packages/evershop/src/modules/catalog/services/registerDefaultProductCollectionFilters.js` 209~236행(`ob` 필터, `price`·`name`·`qty`·`status`만). 다른 점: 목록에 없는 값은 거절하지 않고 기본 정렬(`product_id DESC`)로 조용히 바꿉니다. 이것도 안전한 선택입니다. 이 수업 시험은 400을 기대합니다.
