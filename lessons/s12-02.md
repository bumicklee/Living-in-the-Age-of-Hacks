# 12-2 파트너 API: 최소 범위·짧은 수명·회전
⏱ 약 11분 · 고칠 파일 자바 4개(`DaonPartnerController`·새 `DaonPartnerTokenController`·`JwtSigner`·`JwtAuthenticationTokenFilter`) + secure-kit 새 부품(`@PartnerScope`·`PartnerScopeInterceptor`·`PartnerEntrance`) + 설정 3개(`infra/arch.txt`·새 `infra/compose.a09.yml`·`infra/gateway/nginx.conf`) · 아키텍처 **A9** · 방어 스위치 `partner-scope`

범위는 「무슨 기능」, 조회 조건은 「누구의 데이터」입니다. 둘 다 있어야 파트너가 자기 몫만 봅니다.

> 안전 원칙: 파트너 앱 스텁(`stubs/partner`)은 다온마켓 API만 부릅니다(127.0.0.1). 비밀값·고정 키·토큰은 랩 전용 가짜 값이고 화면에 찍지 않습니다.

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=12-2
   make replay T=33 PART=scope   # 배송 파트너가 배정 81건이 아니라 전체 주문 + 내보내기 200 [레드]
   make check L=12-2
   ```
2. **파트너 입구 A9(✏️ `infra/arch.txt`에 `a09`, 새 `infra/compose.a09.yml`, `infra/gateway/nginx.conf`).** 게이트웨이에 파트너 입구 8087을 엽니다: 파트너 앱 → `gateway:8087 /partner/` → mall-portal. 고객 API 입구(8086)의 `/api/partner/`는 404. 앱은 **소켓 주소가 게이트웨이**인 요청만 `/partner/**`로 받습니다(`PartnerEntrance`, 헤더는 믿지 않음). 그래서 앱 직접 주소(8085)·고객 웹(8088)으로 온 파트너 요청도 404입니다.
3. **토큰 발급(✏️ 새 `DaonPartnerTokenController`).** `POST /partner/token`(클라이언트 자격 증명: `client_id`·`client_secret`) → 15분 JWT. 서명은 5-2의 키 체계(OpenBao transit, `kid`)를 그대로 쓰고 **대상만 다르게**(`aud=daon-partner`, ✏️ `JwtSigner.sign(claims, aud)`·`verify(token, aud)`). 내용: `partner_id`·`scope`·`jti`·`exp`. 내보내기 범위 `orders:export`는 기본 발급에서 빠지고, 대장(`daon_partner_app.scopes`)에 있는 범위만 청할 수 있습니다.
4. **범위(✏️ secure-kit `@PartnerScope`·`PartnerScopeInterceptor`).** 목록·상세에 `@PartnerScope("orders:read:assigned")`, 내보내기에 `@PartnerScope("orders:export")`. 문지기 순서: 입구 → 토큰(aud) → 만료 → 범위.
5. **소유(✏️ `DaonPartnerController`).** 조회 조건에 `JOIN daon_partner_order po … AND po.app_id = ?`(2-2의 「소유는 조회 조건이 답한다」). 배정 밖 주문 상세는 404 + `access.denied.not_owner`(actor `partner:courier-01`).
6. **회전.** `POST /partner/credentials/rotate`(지금 비밀값으로) → 새 비밀값(한 번만 보임). 옛 값은 겹침 10분 뒤 거부. 비밀값은 둘(현재·다음)까지, 회전 중 또 회전하면 409.
7. **고객 토큰 필터(✏️ `JwtAuthenticationTokenFilter`).** `/partner/` 경로는 건너뜁니다(파트너 토큰은 문지기가 봅니다).
8. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=33 PART=scope   # 81건에서 멈춤, 내보내기 403 [그린]
   make check L=12-2             # 10개(정상 2개: 파트너 앱 첫 쪽·배정 주문 상세)
   make partner-app              # 파트너 앱 스텁: 받은 주문 81건(방식 token)
   make logs S=mall-portal | grep partner.denied
   make mem                      # 새 컨테이너 없음. 게이트웨이 그대로인지
   ```
9. **스위치.** `make switch K=partner-scope V=off` → `make replay T=33 PART=scope` 레드 → `V=on`.

## 막힐 때
- 범위만 확인하고 조회 조건에 `partner_id`를 빼면 범위 안에서 다시 전체 주문이 보입니다. 범위와 소유는 다른 질문입니다.
- 토큰 수명을 줄이면 파트너 앱이 갱신 로직을 가져야 합니다. 스텁은 `401 invalid_token`(토큰 만료)이면 비밀값으로 한 번 다시 받습니다.
- 회전 중 옛 비밀값을 너무 빨리 끊으면 파트너 장애가 납니다. 겹침 기간을 둡니다.
- 시험의 「16분 뒤」·「11분 뒤」는 랩 시계(A13, `lab:clock:offset`)를 밉니다. 시험이 끝나면 되돌립니다.
- Express: `diffs/s12-02/express.diff`는 같은 교육용 파트너 라우트를 `kit.partnerScope('orders:read:assigned')` + 조회 조건(`daon_partner_order.app_id`)으로 만듭니다(같은 HTTP 시험으로 확인【실측 예정】).

## 남는 이벤트
`partner.denied.scope`(WARN, 한 번이라도) · `partner.denied.token_expired`(INFO, 같은 파트너 20회/10분) · `partner.denied.bad_credential`(WARN, 같은 파트너 5회/10분) · `access.denied.not_owner`(actor `partner:`).
