# 7-6 이미지 서명과 배포 전 확인
⏱ 약 11분 · 고칠 파일 워크플로·compose·배포 스크립트 3개 · 아키텍처 A8 그대로

레지스트리에 쓸 수 있는 다른 사람이나 다른 작업이 같은 태그(`daon/mall-portal:lesson`)에 다른 이미지를 올리면, 태그만 보고 띄우는 배포는 그 이미지를 그대로 띄웁니다. 배포 스크립트가 띄우기 전에 「우리 CI가 서명한 이미지인가」를 확인하게 합니다.

> 랩에서는 스테이징 칸(`daon-staging-mall-portal`, 네트워크 없이 `sleep`만 하는 컨테이너)에 띄우고, 어떤 이미지가 떴는지는 이미지 라벨(`daon.build`)과 이미지 주소로 봅니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=7-6
   make up STACK=spring
   make ci-sim-image-swap     # CI 밖에서 같은 태그에 다른 이미지(라벨 daon.build=unsigned-demo)를 올린다
   make deploy                # 아무 경고 없이 배포된다 → 스테이징 컨테이너 라벨이 unsigned-demo
   make replay T=19           # [레드]
   ```
2. **CI가 서명합니다(✏️ `.gitea/workflows/build.yml`).** 올린 뒤 이미지의 다이제스트(`sha256:…`)를 얻어 `cosign sign --key /keys/cosign.key --tlog-upload=false`로 서명하고, 커밋·작업 번호·시각이 든 **출처 증명**을 `cosign attest`로 붙입니다. 서명 키는 저장소에 없습니다: 랩이 만든 키 한 쌍이 도커 볼륨에 있고 러너가 읽기 전용으로 받습니다(✏️ `compose.a08.yml`의 `ci-keys` 마운트·`COSIGN_PASSWORD`). 공개 투명성 로그는 쓰지 않습니다(랩은 PC 안에서만 돎. 회사에서는 켭니다).
3. **배포 전에 확인합니다(✏️ `tools/deploy/deploy.sh`).** 순서: ① 태그가 가리키는 다이제스트를 정한다(못 정하면 거부) → ② 공개 키로 서명을 확인한다(없으면 거부) → ③ 출처 증명의 커밋이 CI 저장소 `main`에 있는지 확인한다(없으면 거부) → ④ 통과한 이미지만 태그가 아니라 `@sha256:` 다이제스트로 띄운다. **확인 자체를 못 해도(레지스트리 꺼짐 등) 띄우지 않습니다.** 거부할 때 `deploy.denied.unsigned_image`를 남기고 종료 코드 1로 끝납니다.
4. **확인합니다.**
   ```bash
   make up STACK=spring                       # 바뀐 compose(러너가 서명 키를 읽음) 반영
   make ci-run                                # 서명·출처 증명까지 붙은 이미지
   make deploy ; echo "종료 코드 $?"          # 통과: 다이제스트로 뜸, 라벨 daon.build=ci-lesson
   make ci-sim-image-swap && make deploy ; echo "종료 코드 $?"   # 거부: 서명 없음, 종료 코드 1
   make replay T=19                           # [그린]
   make check L=7-6                           # 6개 통과
   ```

## 막힐 때
- 다음 배포 때 compose를 또 고쳐야 하나요? 다이제스트는 배포마다 바뀝니다. 스크립트가 스테이징 compose 파일(`.daon/ci/deploy/compose.staging.yml`)을 매번 다시 씁니다.
- cosign이 인터넷에 접속하려다 지연되면 투명성 로그를 끄는 옵션(`--tlog-upload=false`·`--insecure-ignore-tlog=true`)을 빠뜨린 것입니다. 이 랩의 확인 도구는 `ci-run` 망(인터넷 없음) 안의 컨테이너에서 돕니다. 확인 때 TUF 경고 한 줄이 보일 수 있습니다.
- 서명 키 비밀번호가 커밋에 들어갔다면 6장의 방법(교체가 먼저)으로 키를 바꿉니다. 이 랩의 키는 도커 볼륨 `daon_ci-keys`에만 있고 git에 들어가지 않습니다.
- Express: `diffs/s7-06/express.diff`는 compose의 이미지를 확인된 다이제스트(`EVERSHOP_IMAGE`)로 받게 합니다. 확인 도구는 두 스택이 같습니다.

## 남는 이벤트
`deploy.denied.unsigned_image`(WARN, reason은 「서명 없음」·「출처 증명의 커밋이 main에 없음」·「확인 불가」 중 하나, target은 `image:daon/mall-portal@sha256:<앞 12자>`)
