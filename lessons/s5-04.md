# 5-4 개인정보 컬럼: 찾기·가리기·원문 보기
⏱ 약 13분 · 고칠 파일 6개 + 새 파일 5개

## 따라 하기
1. **시작 지점(= 5-3 완료)에서 봅니다.**
   ```bash
   make goto L=5-4
   make check L=5-4
   ```
   전화번호 검색이 0건이고, 관리자 회원 목록·주문 상세의 번호가 원문이며, 사유 없이 원문 보기가 막히지 않습니다.
2. **검색용 칸을 만듭니다.** `mall-security/.../crypto/PhoneHmac`(전화번호에서 하이픈·공백을 뺀 뒤 서버만 아는 키로 HMAC-SHA256, OpenBao KV `secret/daon/pii-hmac`의 키), `PhoneIndex`(`ums_member.phone_hmac` 칸과 유일 색인, 번호로 회원 번호를 찾음). 옛 `idx_phone`은 암호문에서 뜻이 없어 검색 칸의 색인으로 옮깁니다.
3. **검색을 고칩니다.** 회원 가입·비밀번호 재설정의 번호 조회(`UmsMemberServiceImpl`)와 관리자 검색(`DaonCustomerSearchController`)이 검색 칸으로 찾습니다.
4. **서버에서 가립니다.** 관리자 회원 목록(`DaonCustomerController`)은 `PiiMask.phone`, 주문 응답의 수령인 번호는 Jackson 믹스인(`PiiMaskJacksonConfig`, `PhoneMaskSerializer`)으로 가립니다(`010-****-0102`).
5. **원문은 사유와 기록으로만.** `DaonPiiRevealController`: `GET /daon/customer/{id}/phone?reason=…` 사유 4자 이상(없으면 400), 한 번에 한 건, 관리자 한 명이 하루 50건(넘으면 429). 이벤트 `pii.reveal`·`pii.reveal.denied`·`pii.reveal.burst`(번호는 남기지 않음).
6. **확인합니다.** `make check L=5-4` 5개 통과, `make check-all` 전체 그린(4-5 SMS 시험도 다시 그린).
7. **스위치.** `make switch K=pii-mask V=off`는 가리기·검색 칸·사유 확인을 끕니다(앱 재시작 뒤 5-3 완료 상태).

## 키를 바꾸면
검색 칸은 키 버전과 함께 저장하고, 키를 바꾸면 모두 다시 계산합니다(랩은 회원 50명 1초 안팎).
