# 7-5 로컬 CI 만들기와 CI 도구 고정
⏱ 약 12분 · 고칠 파일 워크플로·compose·설정 4개 + 새 파일 2개 · 아키텍처 A8(`infra/compose.a08.yml`, `infra/gitea/`, `infra/ci-broker/`, `infra/ci-tools/`)

> 이 랩이 만든 범위: 로컬 Gitea(저장소·CI) + 러너 + 레지스트리 + 단기 자격증명 발급기(`ci-broker`). 7-4 사고 수업이 끝나면 이 뼈대가 먼저 서 있습니다(`make up`이 함께 띄움). 네 서비스의 실사용 메모리는 이 PC에서 쉴 때 약 235MiB였고, 설정한 상한의 합은 약 1.3GB입니다. 이 수업에서 고치는 것은 「외부 단계 고정」「러너 권한」「장기 키」입니다. 이미지를 만드는 일은 러너 밖의 빌드 단계(`make ci-build`)가 하고, 러너는 그 결과 파일을 받아 레지스트리에 올립니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=7-5
   make up STACK=spring       # A8이 같이 뜬다(Gitea http://127.0.0.1:3300, 레지스트리 127.0.0.1:5050)
   make ci-run                # 첫 push → 빌드 → 이미지가 레지스트리에 올라간다(성공)
   make ci-runner-status      # 러너 권한: user=root, 도커 소켓 마운트 …
   make replay T=18           # 태그를 옮기면 바뀐 단계가 실행된다(환경 변수 이름이 로그에 보임)
   make check L=7-5
   ```
   재연은 로컬 Gitea 안에서만 외부 단계 `daon-lab/scan-step`의 `v1` 태그를 다른 커밋으로 옮깁니다. 우리 CI 파일은 한 글자도 바뀌지 않는데, 바뀐 단계가 장기 키(`REGISTRY_PASSWORD`)가 있는 환경에서 돕니다. 옮긴 단계는 환경 변수의 **이름**만 출력합니다(값은 출력하지 않음).
2. **외부 단계를 커밋 해시로 고정합니다(✏️ `.gitea/workflows/build.yml`).** `uses: daon-lab/scan-step@v1`을 40자 해시로 바꾸고 옆 주석에 원래 태그를 적습니다. 해시는 `daon-lab/scan-step`의 처음 커밋(`5a5d19082b7b…`)이고, `ci/pins.lock`에 이름·해시·확인 날짜를 적습니다(새 파일).
3. **고정 검사를 첫 작업으로 둡니다(✏️ 새 파일 `tools/ci/check_pins.py`).** `uses:`의 `@` 뒤가 40자 16진수가 아니면 `ci.denied.unpinned_step`, `pins.lock`과 다르면 `ci.step.changed`를 남기고 종료 코드 1로 끝냅니다. 같은 검사를 `make ci-lint`로 PC에서도 돌립니다. 워크플로는 `lint` 작업이 통과해야 `publish`가 시작하게(`needs: lint`) 바꿉니다.
4. **장기 키를 지웁니다(✏️ `infra/gitea/seed/secrets.list`, 워크플로).** 저장소 비밀값 `REGISTRY_PASSWORD`를 목록에서 지우고, 올리는 단계는 작업이 도는 동안만 쓰는 단기 계정으로 바꿉니다: 작업 토큰(`gitea.token`)을 `ci-broker`에 내밀면 10분 안(또는 작업이 끝날 때까지)에 사라지는 계정(`job-…`)을 줍니다.
5. **러너를 최소 권한으로(✏️ `infra/compose.a08.yml`).** 비루트(`user: "10002:10002"`), `read_only`, `cap_drop: [ALL]`, `no-new-privileges`, **도커 소켓 마운트 삭제**. 러너는 바깥 인터넷도 앱·저장소 망도 못 보는 `ci-run` 망에만 있습니다.
6. **확인합니다.**
   ```bash
   make up STACK=spring                   # 바뀐 compose를 반영
   make ci-run && make replay T=18        # 태그를 옮겨도 고정된 해시의 단계만 돈다 → [그린]
   make check L=7-5                       # 11개 통과
   ```
   일부러 `@v1` 줄을 넣고 `make ci-run` 해 보세요: `lint`가 실패하고 `publish`는 시작도 하지 않습니다.

## 막힐 때
- 처음 `make up`은 러너 이미지를 만들고 Gitea를 준비하느라 몇 분 걸립니다. 8GB PC에서는 `make down STACK=express`로 Express 스택을 먼저 내리세요(`make mem`으로 확인).
- 러너가 「오프라인」으로 남으면 `make ci-runner-status`, `make logs S=runner`. 3300·5050 포트가 이미 쓰이면 `infra/.env`의 `DAON_CI_PORT`·`DAON_CI_REGISTRY_PORT`를 바꿉니다.
- 고정 검사가 해시를 거부하면 7자 짧은 해시를 적은 것입니다. 40자 전체를 적습니다.
- 작업 로그 끝에 「Post … 실패」 줄이 보일 수 있습니다. 러너의 읽기 전용 파일 시스템 때문에 외부 단계의 뒷정리가 한 줄 실패하는 것이고 작업 결과에는 영향이 없습니다.
- Express: `diffs/s7-05/express.diff`는 이미지 빌드 파일을 `npm ci` + 비루트(`USER node`)로 바꿉니다(E25).

## 남는 이벤트
`ci.denied.unpinned_step`(WARN) · `ci.step.changed`(WARN). CI 로그와 `reports/security-events.jsonl`에 함께 남습니다.
