# 9-1 정규식 하나로 27분 멈춘 CDN
⏱ 약 8분 · 사고 수업(고치기 없음, `make check` 없음) · 아키텍처 변화 없음 · 재연 T23(측정만)

## 따라 하기
1. **시작 지점으로 갑니다.**
   ```bash
   make goto L=9-1
   make up STACK=spring
   ```
2. **쿠폰 코드 확인 API를 봅니다([교육용 추가] `DaonCouponController`).** 쿠폰 코드는 대문자·숫자 덩어리를 하이픈으로 이은 모양(`DAON-2026-SPRING`)이고, 시작 코드는 1~3글자씩 겹쳐 읽는 갈래를 반복한 정규식으로 검사합니다. 같은 `A`들을 여러 갈래로 다시 나눌 수 있어 끝에서 실패하는 입력이 길어지면 느려집니다.
   ```bash
   make replay T=23      # 길이별 처리 시간 표 [레드]
   ```
3. **길이별 시간을 잽니다.**
   ```bash
   make measure M=regex
   ```
   - 입력은 `AAAA…A!`(맨 끝 한 글자만 규칙 밖)입니다. 엔진은 「맞지 않는다」를 알기까지 A들을 덩어리로 나누는 모든 방법을 시도합니다. 한 글자 늘 때마다 방법의 수가 두 배입니다.
   - 길이 14자부터 한 글자씩, 한 번에 요청 하나, 요청마다 2초 제한, 1초를 넘는 길이가 나오면 멈춥니다(최대 28자, 15개 이하). 이 상한은 `replay/_faults.py`에 박혀 있고 인자로 바꿀 수 없습니다.
   - 절대값은 PC마다 다릅니다. 몇 글자 늘었을 뿐인데 시간이 두 배씩 뛰는 **모양**을 봅니다.
4. **식힙니다.** 2초 제한으로 끊어도 서버 스레드는 계속 돌 수 있습니다.
   ```bash
   make measure-cooldown     # mall-portal CPU가 20% 아래로 내려갈 때까지(최대 60초)
   ```
5. **Spring과 Node의 차이(그림).** Spring은 요청마다 스레드가 있어 그 요청만 바쁩니다. Node(EverShop)는 이벤트 루프가 하나라 같은 입력 하나가 다른 요청까지 세웁니다. 이 랩은 EverShop에 느린 경로를 더하지 않았습니다(그림으로만).

## 막힐 때
- 표가 다 빠르다(0.1초 안): JIT·CPU에 따라 다릅니다. `make measure M=regex`를 한 번 더 돌리면 대개 커집니다. 28자에서도 빠르면 그 값을 실측 메모로 남깁니다.
- 28자를 넘는 입력은 400 「랩 안전 장치」입니다. 수업의 고치기가 아니라 PC를 지키는 장치입니다(9-3에서 진짜 상한 20자를 둡니다).
- `mall-portal`은 `cpus: 2`(`infra/compose.lab.yml`)로 묶여 있어 측정 중에도 PC 전체가 멈추지 않습니다.

## 남는 이벤트
없음. 이런 장애는 오류 로그가 아니라 **지연과 CPU**로 먼저 보입니다. 9-3에서 길이 상한을 넘는 입력을 `input.denied.too_long`으로 남깁니다.
