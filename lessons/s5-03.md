# 5-3 저장 데이터 암호화: 개인정보 칸을 봉투 암호화로
⏱ 약 14분 · 고칠 파일 5개 + 새 파일 5개 · 아키텍처 A4(OpenBao)

`make dump-db`는 DB와 캐시에 평문 개인정보가 몇 곳 남았는지 건수만 셉니다(값은 찍지 않음).

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=5-3
   make wipe
   make dump-db      # 평문 870곳(회원 전화번호 50 · 주문 전화·주소 365+365 · 배송지 45+45)
   make check L=5-3
   ```
2. **봉투 암호화 도우미를 넣습니다.** `mall-security/.../crypto/`의 `FieldCrypto`(AES-256-GCM 데이터 키를 OpenBao `daon-pii`로 감싸 `daon_data_key` 표에 보관, 값은 `enc:1:<키번호>:<내용>` 모양), `EncryptedStringTypeHandler`(MyBatis가 저장할 때 잠그고 읽을 때 풉니다), `PiiMask`.
3. **칸에 붙입니다.** 생성된 매퍼 XML 세 개(`UmsMemberMapper`·`OmsOrderMapper`·`UmsMemberReceiveAddressMapper`)의 전화번호·주소 칸에 `typeHandler`를 답니다(✏️ 5-3 표시). 회원 캐시(`UmsMemberCacheServiceImpl`)에는 가린 전화번호만 넣습니다.
4. **기존 평문을 한 번 잠급니다.** 랩 전용 `PiiReencrypt`가 앱이 뜰 때 기존 행을 암호화합니다(`DAON_PII_MIGRATE=true`인 회원 앱 하나, 약 1분 안팎).
5. **확인합니다.** `make dump-db`가 `평문으로 읽히는 곳: 0`, `make check L=5-3` 5개 통과. 관리자·고객 주문 상세의 전화번호는 정상으로 보입니다.
6. **스위치.** `make switch K=pii-encrypt V=off`면 새로 저장하는 값이 평문입니다(앱 재시작 뒤).

## 이 수업이 일부러 깨뜨리는 것
전화번호로 회원을 찾는 기능(관리자 검색, 가입 중복 검사, 비밀번호 재설정)이 암호문과 비교하게 되어 0건이 됩니다. 5-4가 고칩니다. 전체 시험(`make check-all`)에서 전화번호로 찾는 4-5 시험은 5-3 완료 지점에서 레드입니다.

## 남는 이벤트
`crypto.decrypt.failed`(값이 바뀌었거나 키가 틀림, 암호문·평문은 남기지 않음) · OpenBao 감사 로그에 데이터 키 풀기 기록
