# 3-4 상품 후기가 관리자 화면에서 실행된다(저장형 XSS)
⏱ 약 11분 · 고칠 파일 2개(관리자 화면 Vue 1, 고객 앱 서비스 1) · 바뀌는 줄 약 30줄

다온마켓은 작은 후기 기능을 새로 넣었습니다([교육용 추가]). 쓴 사람은 고객이고, 보는 사람은 관리자입니다.

| 넣은 것 | 앱 | 내용 |
|---|---|---|
| `POST /daon/review` | mall-portal | 로그인한 고객이 후기를 쓴다(원본 표 `pms_comment`) |
| `GET /daon/review/list` | mall-admin | 후기 목록(최신 20개). 상품 관리 권한(`/product/**`)과 같은 권한 |
| 「상품 후기(교육용)」 화면 | mall-admin-web | http://127.0.0.1:8090/#/daon-review · 본문을 `v-html`로 그린다 |

관리자 화면 시험은 진짜 브라우저(Playwright, 헤드리스 Chromium)로 엽니다. `make setup`이 설치합니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=3-4
   make replay T=07
   make check L=3-4
   ```
   alice가 태그가 섞인 가짜 후기를 쓰고(본문은 재연 스크립트 안에), 상품 담당 직원 `staff_goods`가 후기 화면을 엽니다. 후기 칸에 글자 대신 그림 요소(`img`)가 그려지고, 랩 표시용 처리기가 실행되어 탭 이름이 「[교육용 랩] 후기 스크립트가 실행됨」으로 바뀝니다. 밖으로는 아무것도 보내지 않습니다.
2. **토큰은 어디에 있나(개발자 도구로 보기).** 관리자 화면에 로그인한 뒤 개발자 도구 → Application → Local Storage → `http://127.0.0.1:8090`의 `user` 키를 엽니다(값은 가리고 봅니다). 로그인 토큰(`token`)과 **입력한 비밀번호 원문(`password`)**이 함께 들어 있습니다(`stores/user.ts`, pinia 영속 저장). 쿠키는 없습니다. 이 화면에서 스크립트가 한 번이라도 실행되면 두 값 모두 스크립트 손에 닿습니다.
3. **출력에서 막습니다(본 방어).** `spring/mall-admin-web/src/views/pms/review/index.vue`의 ✏️ 3-4 표시.
   ```vue
   <template #default="{ row }"><div class="review-text" :data-testid="`review-content-${row.id}`">{{ row.content }}</div></template>
   ```
   ```css
   .review-text { white-space: pre-line; }   /* v-html을 지우면 사라지는 줄바꿈을 CSS로 살린다 */
   ```
   - Vue의 `{{ }}`는 글자로 내보냅니다. 「출력하는 곳의 문법에 맞춰 바꾼다」가 원칙입니다.
   - 이 수업은 본문 칸만 고칩니다. 같은 화면의 다른 칸은 섹션 미션에서 봅니다.
4. **입력에서 한 번 더(보조).** `spring/mall-portal/.../service/impl/DaonReviewServiceImpl.java`의 ✏️ 3-4 표시. 길이 상한 500자, 본문은 원래 글자 그대로 저장합니다.
   ```java
   if (content.length() > MAX_CONTENT) {
       Asserts.fail("후기는 " + MAX_CONTENT + "자까지 쓸 수 있습니다");
   }
   ```
   - 꺾쇠를 `&lt;`로 바꿔 저장하지 않습니다. 화면에 `&lt;`가 그대로 보이는 이중 인코딩이 생깁니다.
   - 서식이 꼭 필요한 곳(상품 상세 HTML)은 서버에서 허용 태그만 남기는 정리 라이브러리를 씁니다. 원본에 이미 있는 hutool(`cn.hutool.http.HtmlUtil`, `HTMLFilter`)이나 jsoup `Safelist`가 후보입니다. 후기는 서식이 필요 없어 쓰지 않습니다.
5. **⑤ 탐지.** 관리자 화면은 브라우저라 서버 로그가 없습니다. 후기를 저장할 때 태그처럼 보이는 것의 **이름만** 남깁니다(본문은 남기지 않음). 정상 고객은 후기에 태그를 쓰지 않습니다.
   ```java
   Set<String> tags = tagNames(content);           // <\s*/?\s*([a-zA-Z][a-zA-Z0-9-]*) · 「1<2」는 태그가 아니다
   if (!tags.isEmpty()) {
       SecurityEventLogger.suspicious("input.sanitized.html", "3-4")
               .actor("member:" + member.getId())
               .target("review:" + c.getId())
               .reason("허용 밖 태그 발견: " + String.join(",", tags))
               .log();
   }
   ```
6. **확인합니다.**
   ```bash
   make check L=3-4      # 관리자 화면 이미지도 다시 빌드합니다(1분쯤)
   make replay T=07      # [그린] 후기 칸 요소 0개, 꺾쇠까지 글자로, 탭 이름 그대로
   make logs S=mall-portal | grep input.sanitized.html
   ```
   정상 후기(줄바꿈·이모지·「1<2」)가 그대로 보이는 시험도 그린이어야 합니다.

## Express라면
EverShop에는 후기 모듈이 없습니다. 원본의 HTML 정리 도우미 `express/packages/evershop/src/lib/util/sanitizeHtml.ts`를 「좋은 예」로 봅니다(허용 태그·속성 목록을 명시하고 저장할 때와 그릴 때 같은 규칙). React는 기본으로 글자 출력을 하고, 예외 지점은 `dangerouslySetInnerHTML`입니다.

## 선택: 끄면 레드, 켜면 그린(영상용 방어 스위치)
완료 지점의 목록 API는 `secure-kit.html-sanitize.enabled`를 `textOnly`로 내려 주고, 화면은 그 값이 `false`일 때만 고치기 전처럼 HTML로 그립니다.
```bash
make switch K=html-sanitize V=off   # mall-admin만 다시 띄웁니다
make replay T=07                    # 레드(3-4 완료 지점). 3-5 이후에는 CSP가 막아 그린입니다
make switch K=html-sanitize V=on
```
