# 9-3 입력·압축 해제·페이지 크기 상한, 선형 정규식 + HTTP/2 설정 점검
⏱ 약 11분 · 고칠 파일 자바 2개(`DaonCouponController`·`OmsCartItemController`)·pom 1개 + 새 파일 3개(`mall-security/.../limits/`) · 아키텍처 변화 없음 · 방어 스위치 `input-limits`

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=9-3
   curl -s "127.0.0.1:8085/product/search?pageSize=100000" | head -c 80; echo
   make logs S=mall-portal | grep "LIMIT 100000"       # 상한 없음(F41)이 SQL에 그대로
   make replay T=23                                    # 9-1의 입력이 아직 느리다 [레드]
   make check L=9-3
   ```
2. **본문 크기 상한(✏️ 새 `mall-security/.../limits/RequestSizeLimitFilter.java`).** 1MB(`DAON_MAX_BODY_BYTES`)를 넘으면 끝까지 읽지 않고 413. Content-Length만 믿지 않고, 청크 전송은 상한 + 1바이트까지만 읽어 봅니다. 파일 업로드(multipart)는 3-6의 상한이 맡습니다. 게이트웨이(nginx `client_max_body_size`)와 앱, 상한은 두 겹입니다.
3. **페이지 크기(✏️ 새 `PageSizeLimitFilter.java`, F41).** 쿼리 문자열의 `pageSize`가 1~100 밖이면 400. 조용히 자르지 않습니다(클라이언트 버그가 드러나게). 두 앱의 목록 API 모두에 걸리도록 필터 하나로 둡니다(`LimitsConfig`가 보안 필터 앞에 등록).
4. **수량(✏️ `OmsCartItemController.java`, F42).** 담기·수량 수정에서 수량이 비었거나 1~99 밖이면 400.
5. **정규식(✏️ `DaonCouponController.java`, pom에 `com.google.re2j:re2j:1.7`).** 순서가 중요합니다: ① 길이 상한 20자를 먼저 ② 정규식은 선형 시간 엔진 RE2/J로. 같은 패턴이 길이에 비례하는 시간만 씁니다. 다른 방법은 패턴을 `^[A-Z0-9]+(-[A-Z0-9]+)*$`로 다시 쓰는 것입니다(갈래가 생기지 않음).
6. **HTTP/2 설정 점검(재연 없음).**
   ```bash
   make config-check C=http2     # 게이트웨이 HTTP/2 사용·동시 스트림 상한·nginx 버전, 게이트웨이 → 앱 HTTP/1.1, 내장 Tomcat·Node 버전
   ```
   Rapid Reset(2023)·CONTINUATION(2024)은 서버 구현의 결함이라 코드로 고칠 것이 거의 없습니다. 버전 패치와 설정 확인이 대책입니다.
7. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=23              # 21자 이상 바로 400, 20자 이하도 0.5초 안 [그린]
   make check L=9-3              # 8개(정상 1개 포함)
   make alert-rules              # 새 이벤트 넷이 Grafana 규칙에
   ```
8. **스위치.** `make switch K=input-limits V=off` → `make check L=9-3` 레드 → `V=on`.

## 막힐 때
- 1.5MB 시험 본문이 413이 아니라 연결 끊김: 남은 본문은 Tomcat이 `max-swallow-size`(기본 2MB)까지만 읽어 버립니다. 그보다 큰 본문은 연결을 끊는 것이 정상입니다.
- RE2/J는 역참조·앞뒤 보기를 지원하지 않습니다. 바꾸기 전에 그 문법을 쓰는지 봅니다.
- `pageSize=0`도 400입니다. 관리자 화면이 0을 보내는 곳이 있으면 그 화면을 고칩니다.
- Express: `diffs/s9-03/express.diff`는 `express.json({ limit: '1mb' })`(압축 해제 뒤 크기 기준), GraphQL 문서 검증 호출 고치기와 깊이 제한(E10, `input.denied.graphql_depth`), 정적 파일 미들웨어가 `next()`로 넘기기(E16)입니다. body-parser·qs·multer 버전 올리기는 7-2의 `overrides` 방식으로(이 diff에는 없음).

## 남는 이벤트
`input.denied.too_large`·`input.denied.page_size`·`input.denied.too_long`(WARN), `input.denied.quantity`(INFO), Express `input.denied.graphql_depth`(WARN).
