# 6-3 시크릿 저장소로 옮기기, 기본값이면 기동 거부
⏱ 약 10분 · 고칠 파일 설정·compose 5개 + 새 파일 8개 · 아키텍처 A4(OpenBao의 KV·database 엔진을 켬)

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=6-3
   make check L=6-3      # 기본값으로 띄워도 거부 줄이 없고, 앱은 고정 계정 reader를 쓰고, reader/123456이 접속됨
   ```
2. **OpenBao에 앱별 경로를 만듭니다(✏️ `infra/openbao/init.sh`).** KV `secret/daon/portal`·`admin`, database 엔진의 역할 `portal`·`admin`(권한 SELECT·INSERT·UPDATE·DELETE만, 1시간짜리 계정), 앱별 정책(자기 경로만). 값은 환경 변수(랩 전용 가짜 값)로만 들어옵니다.
3. **MySQL 준비 한 번(`db-init`, ✏️ `compose.a04.yml`).** 고정 계정 `reader`를 지우고, OpenBao가 동적 계정을 만들 때 쓰는 계정(`openbao`)을 둡니다. 앱은 이 계정을 쓰지 않습니다.
4. **앱이 시작할 때 저장소에서 읽게 합니다.** `DaonVaultPostProcessor`(EnvironmentPostProcessor)가 KV와 동적 DB 자격증명을 읽어 설정 맨 앞에 넣습니다. `LeaseKeeper`가 만료 전에 임대를 늘리고, 못 늘리면 `secret.lease.renew_failed`를 남기고 앱이 스스로 내려갑니다.
5. **기본값이면 시작을 거부합니다.** `StartupSecretCheck`가 DB 비밀번호·모니터링 비밀번호·JWT 서명값이 `known-default-secrets.txt`(6-2 규칙과 같은 목록)에 있으면 `config.startup.denied_default_secret`(설정 키 이름만)을 남기고 멈춥니다.
6. **compose에서 DB·모니터링 비밀번호 환경 변수를 뺍니다**(✏️ `compose.yml`). `infra/secrets/rotation-list.yaml`의 6-3 몫을 `rotated`로 바꿉니다.
7. **확인합니다.** `make check L=6-3` 8개 통과. 앱 로그에 `[6-3] 시크릿 저장소에서 설정 3개를 읽었습니다`, `SELECT CURRENT_USER()`는 `v-portal-…`.
8. **스위치.** `make switch K=startup-check V=off`면 기본값을 넣어도 거부하지 않습니다. 금고에서 받는 부분은 끌 수 없습니다.

## 막힐 때
- OpenBao가 늦게 뜨면 앱이 3초 간격으로 10번 다시 읽어 봅니다. 끝내 못 읽으면 시작하지 않습니다.
- RabbitMQ·MinIO 비밀번호는 서버 쪽 계정을 바꾸는 6-4에서 이 점검 목록에 더합니다.
- DB 역할의 권한(`creation_statements`의 GRANT)을 고쳤다면 **앱을 다시 띄워야** 새 권한이 반영됩니다. 동적 계정은 앱이 시작할 때 새로 만들어지고, 이미 받은 계정은 옛 권한 그대로 임대가 끝날 때까지 남습니다. 권한이 모자라 시험이 깨지면 먼저 앱을 다시 띄워 보세요.
- 운영에서는 AppRole 값을 파일로 넣는 대신 플랫폼의 신원 기능을 씁니다.

## 남는 이벤트
`config.startup.denied_default_secret`(WARN) · `secret.lease.renew_failed`(WARN)
