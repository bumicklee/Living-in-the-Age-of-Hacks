# 11-5 남은 DNS와 메일 서버 설정: 서브도메인 탈취·SMTP 밀반입 점검
⏱ 약 10분 · 고칠 파일 설정 3개(`infra/dns/daon.example.zone`·`infra/mail/postfix-main.cf`·`.gitea/workflows/build.yml`) · 아키텍처 A7 그대로 · 방어 스위치 없음(설정 점검)

지운 지 오래된 행사 페이지의 주소가 아직 우리 도메인 이름으로 남아 있을 수 있습니다. 레코드는 남고 자원은 사라지면, 남이 같은 이름의 자원을 만들어 우리 이름을 씁니다.

> 안전 원칙: 실제 DNS·메일 서버에는 닿지 않습니다. 저장소 안의 영역 파일·자원 목록·메일 서버 설정 사본만 읽습니다. 남의 자원을 확보하는 과정은 다루지 않습니다. 도메인은 모두 `.example`, 주소는 문서용 예약 대역(192.0.2.0/24)입니다.

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=11-5
   make audit-dns             # 주인 없는 레코드 1건(event2025 → 지운 행사 페이지) · 계약 끝난 업체의 SPF include 1건
   make audit-mail            # 패치 전 버전 · 줄 끝 LF 하나를 받아 줌 · 명령 몰아 보내기 허용 · DMARC p=none
   make replay T=32 ; make replay T=31
   make check L=11-5
   ```
   영역 파일(`infra/dns/daon.example.zone`)과 자원 목록(`infra/dns/inventory.yaml`)을 나란히 봅니다. 레코드는 `event2025 CNAME daon-event2025.pages.example.`, 목록에서 그 자원은 `status: deleted`입니다.
2. **DNS(✏️ 영역 파일).** `event2025` 줄을 지우고, SPF에서 `include:_spf.mailer-old.example`을 뺍니다. 런북 한 줄(자원 목록 머리말): **자원을 지울 때는 DNS 레코드를 먼저** 지웁니다. 와일드카드(`*.…`) 레코드는 금지 규칙입니다.
3. **CI(✏️ `.gitea/workflows/build.yml`).** 검사 작업(lint)에 `python3 tools/ci/audit_dns.py`를 더합니다. 점검이 실패하면 올리기(publish)가 시작하지 않습니다.
4. **메일(✏️ `infra/mail/postfix-main.cf`, 회사 메일 서버 설정 사본).** 다온마켓 랩은 주문 메일을 Mailpit(받는 쪽 도구)으로만 보냅니다. 실제 회사라면 확인할 것을 점검표로 둡니다.
   - 패치된 버전(`# mail_version:` 줄)
   - `smtpd_forbid_bare_newline = normalize`(줄 끝이 LF 하나뿐인 줄을 고쳐 읽음) + `smtpd_forbid_bare_newline_exclusions = $mynetworks`
   - `smtpd_data_restrictions = reject_unauth_pipelining`
   - DMARC `p=reject`(영역 파일의 `_dmarc` 줄)
   - 앱이 메일을 만들 때 줄 끝을 CRLF로 쓰는지 봅니다. Spring은 `JavaMailSender`(Jakarta Mail)를 씁니다(점검표의 [참고] 줄).
5. **⑤ 탐지.** 점검 도구도 같은 키의 한 줄을 남깁니다: `config.audit.failed`(actor `ci:audit-dns`·`tool:audit-dns`·`tool:audit-mail`, target `dns:event2025.daon.example` 등). `reports/security-events.jsonl` → 8-4 수집기 → 경보. 운영에서는 매일 한 번 돌립니다.
6. **확인합니다.**
   ```bash
   make audit-dns ; make audit-mail   # 모두 통과
   make check L=11-5          # 7개(정상 2개). 「되살린 레코드를 CI가 막는다」 시험은 A8(로컬 CI)이 떠 있어야 합니다
   make ci-run                # 검사 작업에 DNS 점검 단계가 보이는지
   ```

## 막힐 때
- 자원 목록이 정확하지 않으면 점검이 오탐을 냅니다. 목록 담당을 정합니다(자원 목록 머리말의 `owner`).
- 와일드카드 레코드는 점검이 놓치기 쉽습니다. 규칙으로 금지합니다.
- Express: 같은 영역 파일·스크립트를 쓰므로 코드 diff는 없습니다. EverShop은 메일 발송을 `sendEmail` 서비스(메일 업체 연동 확장)에 맡깁니다. SMTP를 직접 쓰지 않으면 「해당 없음」입니다.

## 남는 이벤트
`config.audit.failed`(WARN, 도구). 경보 후보: 한 번이라도(P2).
