# 10-8 1원에 산 보조배터리: 가격은 서버가 정한다
⏱ 약 11분 · 고칠 파일 자바 4개(`OmsCartItemController`·`OmsCartItemServiceImpl`·`OmsPromotionServiceImpl`·`OmsPortalOrderServiceImpl`) + 새 파일 1개(`CartAddParam`) + 고객 웹 1개 · 아키텍처 변화 없음 · 방어 스위치 `server-price`

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=10-8
   make replay T=37            # 정가 24,000원 SKU 2002가 주문 확인에서 1원 [레드]
   make replay T=46            # 가격 없이 담으면 주문이 500 + trace_id(9-2가 오류 경로만 고쳤다)
   make check L=10-8
   ```
   고객 웹은 지금 가격을 함께 보냅니다(`web/html/app.js`의 장바구니 담기). 화면으로 쓰는 사람에게는 문제가 안 보입니다.
2. **요청 DTO(새 ✏️ `domain/CartAddParam.java`, ✏️ `OmsCartItemController`).** `/cart/add`·`/cart/update/attr`가 엔티티 대신 상품 ID·SKU ID·수량만 받습니다(2-4와 같은 방법). `price`는 옛 요청이 보내는 값을 받아만 두는 칸입니다: SKU 가격과 다르면 `price.tampered`를 남기고 **서버 가격으로 담습니다**(거절은 ④에서만).
3. **담기(✏️ `OmsCartItemServiceImpl.add`).** `pms_sku_stock`·`pms_product`에서 가격·이름·SKU 코드를 채웁니다. SKU가 없거나 상품과 짝이 안 맞으면 400. 규격 바꾸기(`updateAttr`)는 **내 줄일 때만** 지웁니다(원본은 줄 ID만으로 지워 남의 줄도 지울 수 있었습니다).
4. **확인·생성 공통 경로(✏️ `OmsPromotionServiceImpl.calcCartPromotion`).** 할인 갈래 다섯 개(단품, 계단 충족·미충족, 만원 충족·미충족, 할인 없음) 모두에서 `setPrice(skuStock.getPrice())`. 단품 할인 갈래가 원래 하던 일을 나머지에도. 계단·만원 「충족」 갈래는 할인액을 SKU 가격으로 계산하므로, 요청 가격이 낮으면 금액이 음수가 될 수 있었습니다.
5. **생성 직전 마지막 대조(✏️ `OmsPortalOrderServiceImpl.generateOrder`).** 주문 항목 가격을 정하기 직전에 SKU 가격과 다시 비교, 다르면 주문을 만들지 않고 「가격이 바뀌었습니다」 + `price.tampered`. ③이 있으면 걸릴 일이 없어야 하지만 둡니다.
6. **고객 웹(✏️ `web/html/app.js`).** 장바구니 담기에서 `price`(와 이름 등)를 보내지 않습니다.
7. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=37            # 정가 [그린]
   make replay T=46            # 가격 없이 담아도 정가 주문(만든 주문은 닫음)
   make check L=10-8           # 8개(정상 3개 포함)
   ```
   사후 점검 SQL(막기 전 흔적): `SELECT i.order_id, i.product_sku_id, i.product_price, s.price FROM oms_order_item i JOIN pms_sku_stock s ON s.id = i.product_sku_id WHERE i.product_price < s.price AND IFNULL(i.promotion_amount,0) = 0;`
8. **스위치.** `make switch K=server-price V=off` → `make replay T=37` 레드 → `V=on`.

## 막힐 때
- ③만 고치고 ②를 빼면 장바구니 목록에 1원이 계속 보입니다. 담는 순간부터 서버 값으로.
- 할인 갈래 하나만 고치면 조건에 못 미친 계단·만원 할인 상품에서 다시 뚫립니다.
- 단품 할인 상품 금액이 바뀌었다: `setPrice`를 할인 계산 뒤에 두었는지 봅니다(정상 시험 `test_single_item_promotion_unchanged`).
- Express: EverShop은 장바구니 가격을 상품 표에서 다시 읽습니다(`registerCartItemBaseFields.js`, 좋은 예). `diffs/s10-08/express.diff`는 담기 요청에 가격이 섞여 오면 무시하고 `price.tampered`만 남기는 몇 줄입니다.

## 남는 이벤트
`price.tampered`(WARN, actor `member:<ID>`, target `sku:<ID>`, reason 「요청 가격이 SKU 가격과 다름(서버 가격으로 처리)」·「주문 직전 가격 불일치(주문 거절)」). 보낸 가격 값은 넣지 않습니다. 고객 웹은 이제 가격을 보내지 않으므로 정상 사용자에게서 나올 수 없습니다: 한 번이라도 경보.
