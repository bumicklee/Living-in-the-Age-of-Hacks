# 3-5 출력 인코딩·CSP·쿠키 속성
⏱ 약 8분 · 고칠 파일 2개 + 새 파일 1개(관리자 화면 nginx 설정, 관리자 앱 설정, 위반 보고 받기) · 바뀌는 줄 약 100줄(새 컨트롤러 82줄 포함)

3-4는 한 칸을 고쳤습니다. 다음 기능에서 누군가 또 `v-html`을 쓸 수 있습니다. **CSP**(Content-Security-Policy)는 출력 인코딩을 빠뜨렸을 때 브라우저가 한 번 더 막게 하는 응답 헤더입니다.

## 따라 하기
1. **인코딩이 빠진 상태를 일부러 만듭니다.** 방어 스위치를 수업 본문에서 쓰는 첫 장면입니다. 실습 코드는 바뀌지 않습니다.
   ```bash
   make goto L=3-5
   make switch K=html-sanitize V=off   # 3-4 보호를 끈다
   make replay T=07                    # [레드] 탭 이름이 바뀐다
   make check L=3-5                    # CSP 시험 셋이 레드
   ```
2. **관리자 화면에 CSP를 겁니다.** `infra/lab-banner/admin-web.conf`의 ✏️ 3-5 표시. 관리자 화면을 내보내는 nginx 설정입니다(게이트웨이는 6-4에서 생깁니다).
   ```nginx
   add_header Content-Security-Policy "default-src 'self'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob: http: https:; font-src 'self' data:; connect-src 'self' http://127.0.0.1:* http://localhost:*; object-src 'none'; base-uri 'self'; frame-ancestors 'none'; report-uri /api/daon/csp-report" always;
   ```
   - 핵심은 `script-src 'self'`입니다. 우리 서버의 스크립트 파일만 실행하고, 글 속에 섞인 인라인 처리기(`onerror=` 같은 속성)는 막습니다.
   - `connect-src`: 관리자 화면은 다른 포트의 관리자 API(127.0.0.1:8080)를 부릅니다. 빠뜨리면 로그인부터 막힙니다.
   - `style-src 'unsafe-inline'`: 「교육용 랩」 띠와 Element Plus가 인라인 스타일을 씁니다. 스타일 허용은 스크립트 허용보다 위험이 작습니다.
   - `img-src`: 상품 사진 주소가 여러 곳이라 이미지 출처는 넓게 둡니다.
   - 처음 거는 서비스라면 `Content-Security-Policy-Report-Only`로 보고만 먼저 받아 보고, 고친 뒤 막습니다.
   - 정답 파일은 스위치(`headers`)를 읽으려고 이 헤더 값을 `map`으로 고릅니다. 손으로 고칠 때는 위 한 줄이면 됩니다.
3. **위반 보고를 같은 출처로 받습니다.** 같은 파일에 `location = /api/daon/csp-report`를 두고 관리자 API로 넘깁니다(`client_max_body_size 16k`). 관리자 앱에는 받는 곳을 만듭니다.
   - `spring/mall-admin/.../daon/DaonCspReportController.java`(새 파일): `POST /daon/csp-report`, 본문 8KB 상한, 지시어 이름과 막힌 출처(inline·eval 또는 호스트)만 꺼냅니다.
   - `spring/mall-admin/src/main/resources/application.yml`: 브라우저는 로그인 없이 보고를 보내므로 `secure.ignored.urls`에 `/daon/csp-report`를 더합니다.
4. **⑤ 탐지.** 보고는 누구나 위조할 수 있어 INFO로 시작하고, 같은 페이지에서 반복되는지 봅니다. 보고 본문 전체는 남기지 않습니다.
   ```java
   SecurityEventLogger.suspicious("csp.violation", "3-5")
           .actor("anonymous")
           .target("directive:" + directive)     // 인라인 처리기는 script-src-attr로 온다
           .reason("막힌 출처: " + blocked)       // inline
           .request(request)
           .log();
   ```
5. **확인합니다.** 스위치를 끈 채로:
   ```bash
   make check L=3-5      # 관리자 화면 nginx를 다시 띄우고 시험
   make replay T=07      # [그린] 후기 칸에는 img가 그려지지만 처리기는 실행되지 않음(현재 문서의 DOM CSP 위반 이벤트)
   make logs S=mall-admin | grep csp.violation
   make switch K=html-sanitize V=on    # 다시 켠다
   ```
   로그인·상품 목록·후기 목록·「교육용 랩」 띠가 정상인지 보는 시험도 그린이어야 합니다.

## 쿠키 속성
| 속성 | 막는 것 | 다온마켓 |
|---|---|---|
| HttpOnly | 스크립트가 쿠키 값을 읽는 것(피해를 줄일 뿐, XSS를 막지는 않는다) | 관리자 토큰은 쿠키가 아니라 Local Storage에 있어 줄 수 없다(3-4 2단계) |
| Secure | HTTPS가 아닌 연결로 쿠키가 가는 것 | Express는 운영 모드에서 꺼 둔다(E02) |
| SameSite | 다른 사이트에서 시작된 요청에 쿠키가 실리는 것(CSRF) | Express 세션 쿠키에 지정이 없다(E03) |

관리자 토큰 보관 방식을 바꾸는 일(쿠키로 옮기면 CSRF·CORS가 함께 걸린다)은 뒤 수업에서 다룹니다.

## Express라면
`diffs/s3-05/express.diff`. `X-Powered-By` 끄기(`app.js`), 모든 응답에 `X-Content-Type-Options`·`Referrer-Policy`·`Content-Security-Policy`(`object-src 'none'; base-uri 'self'; frame-ancestors 'none'`), 상점 화면은 인라인 스크립트를 써서 `script-src 'self'`는 `Report-Only`로 먼저. 세션 쿠키 `sameSite: 'lax'`, `saveUninitialized: false`, 운영 모드 `secure: true`.
```bash
cd express && git apply ../diffs/s3-05/express.diff
```
