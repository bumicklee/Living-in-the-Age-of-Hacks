# 6-6 보안 헤더·CORS·쿠키 기본값
⏱ 약 7분 · 고칠 파일 자바·설정 6개 + 새 파일 3개

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=6-6
   make check L=6-6    # 이 랩 안의 가짜 출처(evil.example) 사전 요청도 그대로 허용되고, 보안 헤더가 없음
   ```
2. **CORS를 허용 출처 목록으로(✏️ 두 앱 `GlobalCorsConfig`).** `addAllowedOriginPattern("*")` + 자격증명 허용은 요청 출처를 그대로 반사합니다. `daon.cors.allowed-origins`(고객 웹 8088, 관리자 웹 8090)에 있는 출처만, 정확 일치로, 자격증명 허용도 그 목록에만. 메서드·헤더도 쓰는 것만.
3. **보안 헤더를 붙입니다.** `SecurityHeadersFilter`(API 응답)와 화면 nginx 두 곳(✏️ `admin-web.conf`·`web/nginx.conf`): `X-Content-Type-Options`·`Referrer-Policy`·`X-Frame-Options`·`Permissions-Policy`, `Server` 버전 숨김. HSTS는 HTTPS 입구에서만(랩 127.0.0.1 HTTP에는 붙이지 않음). CSP는 3-5에 있습니다.
4. **목록 밖 출처를 기록합니다.** `OriginWatchFilter`가 `cors.denied_origin`(INFO)을 남깁니다(출처는 120자까지).
5. **확인합니다.** `make check L=6-6` 11개 통과.
6. **스위치.** `make switch K=cors-allowlist V=off`면 옛 반사 설정, `K=sec-headers V=off`면 API 응답에 헤더가 빠집니다.
7. **Express.** `diffs/s6-06/express.diff`(상태를 바꾸는 요청의 Origin 검사). 쿠키·헤더는 3-5 diff에서 이미 고쳤습니다.

## 막힐 때
- 출처 비교를 `contains`로 하면 `127.0.0.1.evil.example`이 통과합니다. 정확 일치로 비교합니다.
- 게이트웨이(A1)는 6-4에서 붙습니다. 이 수업의 헤더는 앱과 화면 nginx에 직접 붙였고, 게이트웨이가 생기면 한 곳으로 모읍니다.

## 남는 이벤트
`cors.denied_origin`(INFO) · `csrf.denied_origin`(WARN, Express)
