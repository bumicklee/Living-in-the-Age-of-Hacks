# 12-4 연동 앱 대장과 대량 내보내기 탐지
⏱ 약 8분 · 고칠 파일 자바 4개(`DaonPartnerController`·`DaonPartnerTokenController`·`PartnerScopeInterceptor`·mall-admin `MallSecurityConfig`) + 새 mall-admin `DaonPartnerAdminController` + 새 경보 규칙 `infra/observability/rules/partner.yaml` + 런북 한 장 · 아키텍처 A9 + A5 · 방어 스위치 `partner-revoke`

사고가 났을 때 「그 앱을 쓰는 곳이 우리 회사에 있는지」부터 찾아야 한다면 이미 늦습니다. 대장·기록·한 번에 끊는 스위치를 미리 둡니다.

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=12-4
   make replay T=33 PART=export  # 분석 파트너가 내보내기 20번(평소의 몇 배): 기록·대장·경보 없음 [레드]
   make partner-audit            # 대장 없음
   make check L=12-4
   ```
2. **대장(✏️ 새 mall-admin `DaonPartnerAdminController`, `MallSecurityConfig`에 `/daon/partner/**` = 관리자 계정 관리 권한).** `GET /daon/partner/apps`: 이름·담당자·범위·상태·계약 만료·마지막 사용·비밀값 회전일·살아 있는 비밀값·토큰 수. 대장 표(`daon_partner_app`)는 12-2부터 있었고 이제 한곳에서 봅니다. 토큰 발급 때 마지막 사용 시각을 갱신합니다(✏️ `DaonPartnerTokenController`).
3. **점검 스크립트.** `make partner-audit`: 90일 넘게 안 쓴 앱, 담당자 없는 앱, 내보내기 범위를 가진 앱, 회전 90일 넘은 비밀값, 계약 끝난 앱.
4. **내보내기 이벤트(✏️ `DaonPartnerController.export()`).** 응답마다 `partner.export`(INFO) 한 줄, `count`에 내보낸 **행 수만**. 응답 본문은 넣지 않습니다.
5. **경보 규칙(✏️ 새 `infra/observability/rules/partner.yaml`).** 파트너별 10분 내보내기 행 수 합계가 기준선(랩 고정 100행)의 3배를 넘으면 `partner.export.bulk` → Mailpit. 8-4 `bulk.yaml`과 같은 방식입니다(이벤트 표에서 만들지 않는 합계 규칙).
6. **앱 단위 일괄 폐기(관리자 앱 `POST /daon/partner/apps/{id}/revoke`, ✏️ `PartnerScopeInterceptor`).** 상태 revoked · 비밀값 둘 다 지금 거부 · 발급 토큰 `jti`를 Redis 폐기 목록(`deny:`, 4-8과 같은 목록)에. 문지기는 폐기 목록을 보고 401 + `partner.denied.revoked`. 범위를 넓히면 `partner.app.changed`(actor `admin:<계정>`). 런북: `docs/runbooks/partner.export.bulk.md`(14장 사고 대응으로).
7. **확인합니다.**
   ```bash
   make up STACK=spring
   make partner-audit            # 90일 안 쓴 앱 legacy-01 · 내보내기 범위 analytics-01
   make replay T=33 PART=export  # 기록·대장·규칙 [그린]. 경보 메일은 1~3분 뒤 http://127.0.0.1:8025
   make partner-revoke APP=courier-01 && make partner-app   # 거절: 401
   make partner-reset            # 랩 값 되돌리기
   make check L=12-4             # 6개(정상 1개: 분석 파트너 내보내기). 경보 메일을 최대 150초 기다린다
   ```
8. **스위치.** `make switch K=partner-revoke V=off` → 폐기한 앱의 토큰이 수명 동안 통과 → `V=on`.

## 막힐 때
- 이벤트에 내보낸 데이터를 넣으면 로그가 또 하나의 유출 통로가 됩니다. 건수만 남깁니다.
- 기준선이 없는 첫 주에는 경보가 뜻이 없습니다. 랩은 고정 값으로 시작합니다(운영은 「지난 7일 같은 시간대 평균의 3배」).
- 일괄 폐기가 비밀값만 지우고 이미 발급한 토큰을 남기면, 토큰 수명(15분) 동안 계속 쓰입니다. 그래서 `jti`도 폐기 목록에 넣습니다.
- 같은 파트너 경보가 이미 떠 있으면 10분 안에 다시 돌려도 새 메일이 오지 않을 수 있습니다(묶음·반복 간격).
- Express: `diffs/s12-04/express.diff`는 같은 이벤트 키의 `partner.export` 한 줄(건수만)입니다.

## 남는 이벤트
`partner.export`(INFO, 경보는 `rules/partner.yaml`) · `partner.app.changed`(WARN, 한 번이라도) · `partner.denied.revoked`(WARN, 한 번이라도 P1: 폐기 뒤에 나오면 도난 토큰 사용 신호).
