# 11-4 남의 계정 페이지가 캐시에 남는다
⏱ 약 11분 · 고칠 파일 설정 2개(`infra/varnish/default.vcl`·`infra/gateway/nginx.conf`) + 새 자바 파일 1개(`mall-portal/.../config/DaonCacheHeaderFilter.java`) · 아키텍처 A7 그대로 · 방어 스위치 `private-cache`

로그인한 사람의 응답이 공용 파일처럼 캐시에 저장되면, 주소만 아는 다른 사람이 그 응답을 받아 갑니다. 캐시 키(주소 + Host)에는 「누가 요청했는지」가 없습니다.

> 안전 원칙: 재연은 랩의 가짜 회원 alice·bob과 랩 페이지(`/api/sso/info`)만 씁니다. 화면에는 회원 번호와 아이디만 보입니다. 구분자·확장자 차이를 이용한 캐시 속임은 원리 그림으로만 다룹니다.

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=11-4
   make replay T=30           # 캐시를 비우고 alice → bob → 토큰 없음. bob이 alice(회원 101) 정보를 X-Cache: HIT로 받음 [레드]
   make check L=11-4
   ```
   시작 VCL(`infra/varnish/default.vcl`)은 A7과 함께 들어온 [회사 설정]입니다. 「/api/ GET은 60초 동안 누구에게나 같은 응답」. Varnish 기본 동작(인증 요청은 pass, 오리진이 no-store면 저장 안 함)을 두 줄(☆)이 덮습니다. mall-portal은 이미 `Cache-Control: no-cache, no-store`(Spring Security 기본값)를 보내지만, 캐시 설정이 그것을 무시했습니다.
2. **캐시(✏️ `infra/varnish/default.vcl`).** ☆ 두 줄을 지우고: `Authorization`·쿠키가 있는 요청은 `pass`. 오리진이 `private`·`no-store`·`no-cache`이거나 `max-age`를 밝히지 않은 응답은 저장하지 않음. 오류 응답(4xx·5xx)은 저장하지 않음.
3. **오리진(✏️ 새 `DaonCacheHeaderFilter.java`).** 로그인한 요청의 응답에 `Cache-Control: private, no-store`, 공개 상품 목록(`/product/search` 등)에 `public, max-age=60`. 캐시 여부는 오리진이 정합니다. Spring Security의 캐시 헤더 작성기는 이미 있는 `Cache-Control`을 덮지 않습니다.
4. **엄격한 라우팅(확인만).** 동적 경로 뒤에 붙은 정적 파일 확장자를 앱이 받아 주지 않는지 봅니다(Spring 6은 확장자 경로 일치를 기본으로 끈다).
5. **⑤ 탐지(✏️ `infra/gateway/nginx.conf`).** 로그인한 요청인데 캐시에서 답했다(`X-Cache: HIT`) → 게이트웨이가 `cache.hit.authenticated` 한 줄. 정상 운영에서는 0이어야 하므로 한 번이라도 경보입니다(배포 직후 캐시 설정이 바뀌는 사고 신호).
6. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=30           # 각자 자기 정보, 인증 요청은 X-Cache: PASS [그린]
   make check L=11-4          # 8개(정상 2개: 공개 상품 목록은 여전히 HIT, alice는 자기 정보)
   docker exec daon-varnish-1 varnishstat -1 -f MAIN.cache_hit -f MAIN.cache_miss
   ```
7. **스위치.** `make switch K=private-cache V=off` → 앱 헤더를 끄고 Varnish가 회사 설정 VCL로 다시 뜸 → `make replay T=30` 레드 + `make logs S=gateway | grep cache.hit.authenticated` → `V=on`.

## 막힐 때
- VCL만 고치고 오리진 헤더를 안 붙이면, 다음에 누가 VCL을 바꿀 때 다시 뚫립니다. 두 겹으로 둡니다.
- 재연을 연달아 돌리면 이전 캐시가 남아 있습니다. 재연·시험은 먼저 비우지만, 손으로 볼 때는 `make cache-purge`.
- 오류 응답을 저장하면 오류 한 번이 모든 사용자에게 퍼집니다(캐시 오염, CPDoS).
- Express: `diffs/s11-04/express.diff`는 고객을 찾은 자리(화면·API 두 곳)에서 `Cache-Control: private, no-store`를 붙입니다(`kit.noStoreAuthenticated()`).

## 남는 이벤트
`cache.hit.authenticated`(WARN, 게이트웨이). 경보 후보: 한 번이라도(P1).
