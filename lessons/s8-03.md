# 8-3 관리자 조회에 감사 로그 남기기
⏱ 약 9분 · 고칠 파일 자바 3개·설정 2개 + 새 파일 3개 · 아키텍처 변화 없음(감사 로그 볼륨 `audit-logs` 추가) · 방어 스위치 `audit-log`

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=8-3
   make replay T=20      # 관리자 회원 목록 × 2 → 감사 로그 0줄 [레드]
   make check L=8-3
   ```
2. **어노테이션과 애스펙트를 만듭니다(✏️ 새 파일 `mall-security/.../audit/Audited.java`·`AuditAspect.java`·`AuditLog.java`).**
   - `@Audited(action = "customer.list", resource = "member")` 한 줄을 붙인 메서드가 끝나면 `AuditAspect`가 8-2의 8개 필드로 한 줄을 씁니다.
   - `count`: 반환 값이 `CommonResult<CommonPage<…>>`면 그 페이지의 `list` 크기, `List`면 크기, 값 하나면 1, `null`이면 0. `total`이 아닙니다.
   - 행위자는 Spring Security 컨텍스트, 사유는 `X-Access-Reason` 헤더(한글은 URL 인코딩), 추적 번호는 MDC(`trace_id`)에서 읽습니다.
   - 예외로 끝난 조회도 `result: error`로 남기고 예외는 그대로 던집니다.
   - 공용 모듈(mall-security)에 둡니다. 15장의 secure-kit 부품 이름과 같습니다.
3. **붙입니다(✏️ `DaonCustomerController.list()`, `OmsOrderController.list()`·`detail()`, `OmsOrderReturnApplyController.list()`).** 넷 중 둘은 손으로, 나머지 둘은 같은 모양이라 빠르게 붙입니다.
4. **다른 파일로 보냅니다(✏️ `mall-common/.../logback-spring.xml`, `infra/compose.yml`).** 로거 `AUDIT`만 `/var/logs/daon/audit.jsonl`(한 줄 JSON, `%msg%n`)로 보내고 `additivity="false"`로 앱 로그에 섞지 않습니다. compose는 mall-admin의 `/var/logs`를 볼륨 `audit-logs`로 붙입니다(8-4에서 수집기가 읽기 전용으로 붙음).
5. **⑤ 탐지: 대량 조회 표시.** `count`가 기준(30) 이상이면 SECURITY `data.read.bulk`(INFO, target `action:customer.list`)를 한 줄 더 남깁니다. 한 요청만 보면 정상 업무와 구별이 어려워 경보가 아니라 8-4 「계정별 누적」 규칙의 재료입니다.
6. **확인합니다.**
   ```bash
   make up STACK=spring           # 볼륨이 붙은 mall-admin으로 다시 뜬다
   make replay T=20               # AUDIT 2줄 ✔ · 경보는 아직 없음(8-4) → 여전히 [레드]
   docker exec daon-mall-admin-1 tail -n 4 /var/logs/daon/audit.jsonl   # count·trace_id를 응답과 맞춰 본다
   make check L=8-3               # 6개 통과(응답 모양이 그대로인지 보는 정상 시험 포함)
   make lab                       # 최근 이벤트 칸에 data.read.bulk
   ```
7. **스위치.** `make switch K=audit-log V=off` → `make check L=8-3` 레드(감사 줄 없음) → `V=on`.

## 막힐 때
- 애스펙트가 걸리지 않는다: 포인트컷이 어노테이션 기준(`@annotation(audited)`)인지, mall-security가 mall-admin의 컴포넌트 스캔 범위(`com.macro.mall`) 안인지 봅니다.
- `additivity="false"`를 빼면 AUDIT 줄이 앱 로그에도 섞입니다(시험이 잡습니다).
- 파일이 안 생긴다: mall-admin을 다시 띄웠는지(`make up`), 볼륨이 `/var/logs`에 붙었는지(`docker exec daon-mall-admin-1 ls -l /var/logs/daon`).
- Express: `diffs/s8-03/express.diff`는 `lib/log/audit.ts`와 관리자 GraphQL `customers`·`customer`·`orders` 처리기의 감사 호출, E18(운영 모드 미기록) 중 오류 쪽은 6-5 diff가 이미 고쳤고, 인증 실패 기록은 8-4 diff(`auth.denied.token`)에 있습니다.

## 남는 이벤트
`data.read.bulk`(INFO). 감사 로그(AUDIT)는 SECURITY 이벤트가 아니라 별도 파일입니다.
