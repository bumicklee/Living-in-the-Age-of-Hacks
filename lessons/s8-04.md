# 8-4 대량 조회·응답 크기·나가는 트래픽 탐지
⏱ 약 12분 · 고칠 파일 자바 2개·관리자 화면 1개 + 새 설정 파일 9개 · 아키텍처 **A5**(`infra/compose.a05.yml`, `infra/observability/`) · 방어 스위치 `status-codes`

> 이 랩이 만든 범위: Loki(로그 저장소) + Alloy(수집기, 도커 API는 읽기 전용 문지기 `docker-proxy`를 거침) + Grafana(대시보드·경보) → 랩 도구 Mailpit(가짜 받은 편지함). 메모리 상한 합계 약 +800MB(실제 사용은 실측 예정). 8GB PC에서는 A8(로컬 CI)을 내리고 진행하세요: `docker stop daon-gitea-1 daon-runner-1 daon-registry-1 daon-ci-broker-1`.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=8-4
   make events-count       # 섹션 2~7에서 심은 줄이 몇 줄 쌓였는지(아무도 읽지 않았다)
   make replay T=20        # 감사 로그는 남는데 아무에게도 알림이 없다 [레드]
   curl -s -o /dev/null -w '%{http_code}\n' http://127.0.0.1:8080/daon/customer/list   # 로그인 없는데 200(F32)
   make check L=8-4
   ```
   F32: 본문은 `code:401`인데 HTTP 상태는 200입니다. 게이트웨이와 모니터링은 상태 코드로 실패를 세므로 실패가 0으로 보입니다.
2. **A5를 켭니다(✏️ `infra/arch.txt`에 `a05`, 새 파일 `infra/compose.a05.yml`·`infra/observability/`).**
   ```bash
   make up STACK=spring && make ps && make mem      # Grafana http://127.0.0.1:3030 (admin / infra/.env의 DAON_GRAFANA_ADMIN_PASSWORD)
   ```
   - 수집기(`alloy/config.alloy`): 다온 컨테이너 로그에서 로거 `SECURITY` 줄의 JSON을 꺼내 `stream=security`와 `event`·`level`·`lesson` 레이블을 붙입니다. 감사 로그 파일은 `stream=audit`, 도구 이벤트 파일(`reports/security-events.jsonl`)은 `stream=tool`입니다. 레이블은 `app`·`stream`·`event`·`level`·`lesson`뿐입니다. `actor`·`trace_id`를 레이블로 두면 Loki가 느려집니다.
   - **거두기:** Grafana 「공격 징후(다온마켓)」 대시보드에 2-2의 `access.denied.not_owner`부터 7-7의 `deserialize.denied.type`까지 수업별·이벤트별로 나타납니다.
3. **경보 규칙을 표에서 만듭니다.**
   ```bash
   make alert-rules        # course/SECURITY_EVENTS.md 「경보 후보(8장)」 → infra/observability/rules/security.yaml, Grafana 다시 띄움
   ```
   「한 번이라도」는 10분 안 1건, 「count ≥ 5 / 10분」은 같은 actor의 10분 합계, 「같은 ip 20회 / 10분」은 ip별 합계가 됩니다. 규칙으로 못 바꾼 줄은 목록으로 알려 줍니다. 만든 파일에서 `access.denied.not_owner` 규칙 하나를 같이 읽습니다.
4. **손으로 세 규칙을 더합니다(✏️ `rules/bulk.yaml`).** 계정별 한도(회원 조회 AUDIT `customer.*`의 `count`를 actor별 10분 합계 > 30. 주문 목록까지 묶으면 주문 관리자의 평범한 사용이 울린다: 실측), 응답 크기(게이트웨이 접근 로그 `bytes`, 관리자 경로별 10분 > 1MB), 나가는 트래픽(이그레스 프록시 로그 바이트 10분 > 5MB). 랩에는 「평소」가 없어 고정 기준을 씁니다. 운영은 지난 기간 같은 시간대를 기준선으로 씁니다.
5. **알림(✏️ `rules/notify.yaml`).** Grafana 연락 지점을 Mailpit(`mailpit:1025`)으로, 제목 `[다온 경보] <event> <actor>`, 본문에는 찾아볼 질의(줄마다 trace_id)를 넣고 개인정보는 넣지 않습니다.
6. **F32를 고칩니다(✏️ `RestAuthenticationEntryPoint`·`RestfulAccessDeniedHandler`, 관리자 화면 `src/utils/http.ts`).** 401·403을 상태 코드로 보내고 본문 모양은 그대로 둡니다. 로그인 없음·만료·서명 불일치는 SECURITY `auth.denied.token`(WARN, 토큰 값은 넣지 않음). 관리자 화면은 axios가 401을 오류 쪽으로 넘기므로 같은 「다시 로그인」 안내를 오류 쪽에도 둡니다.
7. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=20        # 1~2분 뒤 Mailpit(http://127.0.0.1:8025)에 [다온 경보] data.read.bulk admin:admin [그린]
   for i in 1 2 3 4 5 6; do make replay T=01 >/dev/null; done   # [다온 경보] access.denied.not_owner member:102
   make collector-test     # 샘플 SECURITY 줄이 어떤 레이블로 Loki에 들어가는지
   make traffic-normal MIN=10   # 평범한 사용 10분 동안 경보 0통인지(오탐)
   make check L=8-4        # 10개 통과(경보 메일 둘은 최대 150초씩 기다린다)
   ```
   메일의 질의를 Grafana 「Explore」에 붙여 그 요청의 SECURITY·AUDIT 줄을 trace_id로 찾습니다.
8. **스위치.** `make switch K=status-codes V=off` → 로그인 없는 요청이 다시 HTTP 200, 「401(1분)」 패널이 0 → `V=on`.

## 막힐 때
- 메일이 바로 오지 않습니다. 규칙 평가 30초 + 묶음 대기 10초 + 수집 지연 몇 초. 같은 actor의 경보가 이미 울리는 중이면 새 메일은 4시간 뒤에 옵니다(8-7에서 30분으로).
- 수집기가 SECURITY 줄을 못 찾는다: 앱 로그 형식(로거 이름 칸)이 바뀌면 정규식이 깨집니다. `make collector-test`로 확인합니다.
- `make alert-rules` 뒤에도 규칙이 그대로다: Grafana를 다시 띄워야 읽습니다(명령이 함께 합니다).
- 3030·3100 포트가 이미 쓰이면 `infra/.env`의 `DAON_GRAFANA_PORT`·`DAON_LOKI_PORT`를 바꿉니다.
- Express: `diffs/s8-04/express.diff`는 EverShop의 401 경로에 `auth.denied.token`을 남기게 합니다. EverShop은 원래 401 상태 코드를 씁니다(좋은 예). EverShop 컨테이너 로그는 따로 설정하지 않아도 수집기가 같은 규칙으로 읽습니다(SECURITY 줄 형식이 같음).

## 막기 전에 들어온 흔적 찾기(14-4·15-1에서 다시 씀)
```
{event="access.denied.not_owner"} | json | actor="member:102"
```
같은 actor가 거부 뒤 같은 대상에 성공한 기록이 있는지 trace_id로 앱 로그·감사 로그를 이어 봅니다.
