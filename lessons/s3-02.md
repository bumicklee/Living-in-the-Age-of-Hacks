# 3-2 MyBatis `${}`와 문자열 조립 찾기·고치기
⏱ 약 10분 · 고칠 파일 1개 + 새 파일 2개(탐지 1, 검색 스크립트 1) · 바뀌는 줄 약 1줄 + 새 파일 약 100줄

다온마켓은 고객 앱에 상품 검색(`GET /daon/product/search?keyword=&sort=`, 로그인 없이)을 새로 만들었습니다([교육용 추가]). 검색 DAO가 검색어와 정렬 값을 쿼리 문장에 `${}`로 이어 붙입니다. 이 수업은 **검색어 쪽**을 고칩니다. 정렬 쪽은 3-3입니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=3-2
   make replay T=06
   make check L=3-2
   ```
   재연은 검색어 칸의 값만 바꿉니다(값은 재연 스크립트 안에 있습니다).
   - 작은따옴표 하나 → 응답 `message`에 DB 문법 오류 문구(`You have an error in your SQL syntax…`)가 실립니다. 입력이 쿼리 문장의 일부가 됐다는 증거입니다. 오류 문구를 응답에 싣는 원본 공통 처리기는 6-5에서 고칩니다.
   - 조건이 늘 참이 되는 값 → 「이어폰」 검색 결과 1개가 70개로 늘고, 공개하지 않은 상품(231·232)이 섞입니다.
2. **검색어를 바인딩합니다.** `spring/mall-portal/src/main/resources/dao/DaonProductSearchDao.xml`의 ✏️ 3-2 표시.
   ```xml
   and name like CONCAT('%', #{keyword}, '%')
   ```
   - `'%#{keyword}%'`처럼 따옴표 안에 `#{}`를 넣으면 자리 표시자가 되지 않습니다. `%`는 문장 쪽에서 `CONCAT`으로 붙입니다.
   - 정렬 줄(✏️ 3-3)은 그대로 둡니다. 정렬 값은 바인딩으로 고칠 수 없습니다(3-3).
3. **`${`를 찾는 검색 스크립트를 씁니다.** `tools/scan_mybatis_dollar.py`(새 파일). `<mapper`가 있는 XML만 보고, 한 줄의 `${…}`가 모두 `criterion.condition`·`orderByClause`면 「상수」, 아니면 「입력」입니다. 입력이 하나라도 있으면 종료 코드 1.
   ```python
   CONSTANT = re.compile(r"\$\{(criterion\.condition|orderByClause)\}")
   kind = "상수" if all(CONSTANT.fullmatch(m.group(0)) for m in DOLLAR.finditer(line)) else "입력"
   ```
   ```bash
   .venv/bin/python tools/scan_mybatis_dollar.py          # 상수 줄까지 보려면 --all
   ```
   고친 뒤에는 「입력」이 정렬 줄 하나만 남고, 상수는 「매퍼 76개 파일, 692줄」입니다.
4. **⑤ 탐지: SQL 문법 오류 자체를 신호로 남깁니다.** 바인딩 뒤에는 사용자 입력으로 문법 오류가 날 일이 없습니다. `spring/mall-portal/.../portal/config/DaonSqlErrorObserver.java`(새 파일)를 만듭니다. 예외를 먼저 보고 이벤트만 남긴 뒤 처리는 원래 처리기에 넘깁니다(`HandlerExceptionResolver`, `null` 반환).
   ```java
   SecurityEventLogger.denied("db.error.bad_sql_grammar", "3-2")
           .target("path:" + request.getRequestURI())
           .reason("SQL 문법 오류")
           .request(request)
           .log();
   ```
   - 원인 사슬에 `BadSqlGrammarException`이나 `SQLSyntaxErrorException`이 있을 때만 남깁니다. SQL 문장과 입력 값은 넣지 않습니다.
   - 원본 공통 처리기(mall-common)는 로거가 있는 mall-security를 모르므로 고객 앱 쪽에 둡니다.
5. **확인합니다.**
   ```bash
   make check L=3-2
   make replay T=06      # 검색어 두 경우는 그린, 정렬 두 경우는 아직 레드(T06 전체는 3-3까지)
   make logs S=mall-portal | grep db.error.bad_sql_grammar
   ```
   정상 검색 「이어폰」은 고치기 전과 같이 1개(상품 201)입니다.

## SQL 로그로 두 방식 비교하기(선택)
매퍼 로그를 DEBUG로 올리면 `#{}`는 `Preparing: … like CONCAT('%', ?, '%')` 줄과 `Parameters: 이어폰(String)` 줄이 따로 찍힙니다. `infra/compose.yml`의 mall-portal `environment`에 한 줄을 더하고 `make up`:
```yaml
LOGGING_LEVEL_COM_MACRO_MALL_PORTAL_DAO: debug
```

## Express라면
EverShop은 원본이 이미 쿼리 빌더(`@evershop/postgres-query-builder`)로 값을 바인딩합니다. 같은 실수가 없어서 diff 대신 원본을 「좋은 예」로 봅니다.
- 상품 검색어: `express/packages/evershop/src/modules/catalog/services/registerDefaultProductCollectionFilters.js` 11~41행. 검색어를 문장에 넣지 않고 `keyword_<무작위>` 이름의 바인딩 값으로 넘깁니다.
- 다른 곳도 `where('type', '=', 'select')`처럼 컬럼·연산자·값을 따로 넘깁니다.

## 선택: 끄면 레드, 켜면 그린(영상용 방어 스위치)
완료 지점(`make goto L=3-2 AT=done` 또는 그 뒤)의 DAO는 `secure-kit.query-binding.enabled`를 읽습니다. 끄면 고치기 전과 같은 문장을 씁니다.
```bash
make switch K=query-binding V=off   # mall-portal만 다시 띄웁니다
make replay T=06                    # 검색어 ①② 레드
make switch K=query-binding V=on
```

## 기억할 한 줄
값은 `#{}`로 값 자리에만 넣는다. `${`는 검색 스크립트로 계속 지켜본다.
