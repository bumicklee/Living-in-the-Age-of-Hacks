# 10-6 카드 테스팅·사재기·프로모 남용
⏱ 약 9분 · 고칠 파일 자바 2개(`DaonCheckoutController`·`OmsPortalOrderServiceImpl`) + 새 파일 1개(`DaonCheckoutLimiter`) · 아키텍처 변화 없음(A3 Redis 카운터, 가짜 결제사의 가짜 테스트 카드 토큰) · 방어 스위치 `checkout-limits`

## 따라 하기
1. **레드부터 봅니다.** 이 수업은 10-4의 `/pay/start`에 기댑니다.
   ```bash
   make goto L=10-6
   make replay T=27 PART=card    # bob이 거절되는 가짜 토큰 30개 → 30번 모두 결제사까지 [레드]
   make replay T=27 PART=hoard   # 한정 상품(230 「다온 핸드드립 세트」) 20개를 한 계정이 [레드]
   make check L=10-6
   ```
   토큰은 `tok_test_` + 숫자(끝자리 2·4만 승인)인 랩의 가짜 값입니다. 카드 번호 모양은 쓰지 않습니다.
2. **흐름 단위 한도(새 ✏️ `component/DaonCheckoutLimiter.java`, ✏️ `DaonCheckoutController`).** 4-3의 Redis 카운터(`rl:*`, INCR + 첫 EXPIRE를 Lua 한 덩어리)를 세 축으로.
   - 계정 5회/10분 · IP 20회/10분 · 카드 지문 3계정/1일. 결제사를 **부르기 전에** 셉니다. 넘으면 429.
   - 카드 지문은 「fp_ + 토큰 SHA-256 앞 16자」(결제사의 토큰 지문 조회를 흉내, 가짜 결제사와 같은 규칙). 카드 번호는 받지도 남기지도 않습니다.
   - 카드 토큰 모양(`tok_test_` + 숫자)도 먼저 봅니다.
3. **실패율.** 결제사 결과를 10분 창에 더합니다. 시도 10번 이상에서 거절이 절반을 넘으면 창마다 한 번 `payment.suspected.card_testing`(`count`에 거절 수). 랩은 고정 기준선, 운영은 시간대별 기준선.
4. **한정 상품 1인 한도(✏️ `OmsPortalOrderServiceImpl.generateOrder()`).** 설정 `daon.checkout.limited-products`(랩 값 `230:2`). 회원 × 상품 누적 수량을 `daon_purchase_counter`에 10-2와 같은 조건부 UPDATE로(`qty + #{n} <= #{limit}`, 0행이면 거절). 주문이 실패하면 함께 되돌아갑니다.
5. **프로모 남용·대기열은 그림으로.** 가입 쿠폰은 「본인 확인 수단 하나당 1회」, 가상 대기실.
6. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=27 PART=card    # 결제사까지 5번, 나머지 429 [그린]
   make replay T=27 PART=hoard   # 거절 [그린]
   make check L=10-6             # 7개(정상 2개 포함)
   ```
7. **스위치.** `make switch K=checkout-limits V=off` → 두 재연 레드 → `V=on`.

## 막힐 때
- 정상 결제도 429: 앞 재연의 카운터가 남았습니다(10분). `make money-reset`이 `rl:*`를 비웁니다.
- IP 하나로만 걸면 회사망 사용자가 함께 막힙니다. 축을 나눕니다.
- 실패율 경보가 안 뜬다: 한 계정은 5번에서 막혀 시도 10번이 안 됩니다. 계정을 바꿔 가며 거절이 쌓여야 뜹니다(시험은 세 계정 × 4번).
- Express: `diffs/s10-06/express.diff`는 결제 의도 만들기 앞에 계정·IP 카운터 몇 줄과 같은 이벤트입니다.

## 남는 이벤트
`checkout.denied.rate_limit`(WARN, actor `member:<ID>`, reason 「계정·IP·카드 지문 축 결제 시도 한도」, 값 없이 축 이름만), `purchase.denied.per_member_limit`(WARN, target `product:<ID>`), `payment.suspected.card_testing`(WARN, actor `system:checkout`, `count`에 거절 수).
