# 2-4 회원정보 수정으로 등급과 포인트가 바뀐다(대량 할당)
⏱ 약 14분 · 고칠 파일 3개 + 새 파일 1개 · 바뀌는 줄 약 90줄(새 DTO 54줄 포함)

다온마켓은 고객 앱에 회원정보 수정(`POST /sso/updateInfo`)을 새로 넣었습니다([교육용 추가]). 닉네임·도시 같은 항목을 고치라고 만든 기능인데, 요청 본문을 회원 엔티티(`UmsMember`)로 그대로 받아 저장합니다. 엔티티에는 포인트·성장치·등급·상태·비밀번호까지 모든 컬럼이 있습니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=2-4
   make replay T=03
   make check L=2-4
   ```
   alice가 수정 요청 본문에 `"integration": 999999, "growth": 99999, "memberLevelId": 1`을 끼워 보내면 포인트·성장치·등급이 그대로 바뀝니다. 재연은 바뀐 값을 원래대로 되돌려 둡니다.
2. **요청 전용 DTO를 만듭니다.** `spring/mall-portal/.../portal/domain/UmsMemberUpdateParam.java`를 새로 만들고, 회원이 스스로 고칠 수 있는 항목만 둡니다.
   ```java
   @Getter
   @Setter
   public class UmsMemberUpdateParam {
       @Size(max = 64) private String nickname;
       @Min(0) @Max(2) private Integer gender;
       @JsonFormat(pattern = "yyyy-MM-dd", timezone = "Asia/Seoul") private Date birthday;
       @Size(max = 64) private String city;
       @Size(max = 100) private String job;
       @Size(max = 200) private String personalizedSignature;
   }
   ```
   - 포인트·등급·상태는 DTO에 없습니다. 없는 항목은 받을 곳이 없으니 DB까지 갈 수 없습니다.
   - 엔티티에 컬럼이 늘어도 DTO는 그대로입니다. 새 컬럼이 저절로 열리지 않습니다.
3. **컨트롤러·서비스가 DTO를 받게 바꿉니다.** ✏️ 2-4 표시가 세 곳에 있습니다.
   - `UmsMemberController.updateInfo`: `@Validated @RequestBody UmsMemberUpdateParam param`
   - `UmsMemberService.updateInfo(UmsMemberUpdateParam param)`
   - `UmsMemberServiceImpl.updateInfo`: 받은 객체를 그대로 저장하지 말고, 새 `UmsMember`에 허용한 항목만 옮겨 저장합니다.
   ```java
   UmsMember record = new UmsMember();
   record.setId(current.getId());
   record.setNickname(param.getNickname());
   record.setGender(param.getGender());
   // birthday·city·job·personalizedSignature도 같은 방식
   memberCacheService.delMember(current.getId());
   memberMapper.updateByPrimaryKeySelective(record);
   ```
   - 회원 ID는 본문이 아니라 로그인 정보에서 가져옵니다(2-2와 같은 원칙).
4. **⑤ 탐지: 허용 밖 항목이 섞인 요청을 남깁니다.** 막는 것은 DTO가 이미 했습니다. 다만 정상 화면은 `integration`을 보내지 않으므로, 보냈다면 누군가 요청을 손으로 만들고 있다는 뜻입니다.
   - DTO에 무시한 항목 이름을 모으는 `@JsonAnySetter`를 둡니다(값은 버립니다).
   ```java
   @JsonIgnore
   private final Set<String> ignoredFields = new TreeSet<>();

   @JsonAnySetter
   public void ignore(String name, Object value) {
       if (ignoredFields.size() < 20) ignoredFields.add(name.length() > 40 ? name.substring(0, 40) : name);
   }
   ```
   - 서비스에서 저장한 뒤 의심 이벤트(INFO)를 남깁니다.
   ```java
   if (!param.getIgnoredFields().isEmpty()) {
       SecurityEventLogger.suspicious("input.unexpected_fields", "2-4")
               .actor("member:" + current.getId())
               .target("member:" + current.getId())
               .reason("허용 밖 항목 무시: " + String.join(",", param.getIgnoredFields()))
               .log();
   }
   ```
   - 항목 이름만 남기고 보낸 값(999999 같은 숫자, 비밀번호)은 남기지 않습니다.
5. **확인합니다.**
   ```bash
   make check L=2-4
   make replay T=03      # [그린] 막힘
   make logs S=mall-portal | grep input.unexpected_fields
   ```
   alice가 닉네임·도시를 고치는 정상 요청 시험도 그린이어야 합니다.

## Express라면
`diffs/s2-04/express.diff`. EverShop의 고객 프로필 수정(`PATCH /api/customers/me`)은 본문 전체를 받고 보호 필드만 빼는 방식(막을 목록)입니다. 원본도 그룹·상태는 막지만, 받을 항목만 고르는 목록(`ALLOWED = ['full_name', 'email']`)으로 바꾸면 새 컬럼이 생겨도 열리지 않습니다.

## 선택: 끄면 레드, 켜면 그린(영상용 방어 스위치)
완료 지점(`make goto L=2-4 AT=done`, 또는 그 뒤 수업)의 정답 코드는 `secure-kit.request-dto.enabled` 스위치를 읽습니다. 코드를 고치지 않고 보호를 껐다 켤 수 있습니다. 시작 지점 코드는 스위치를 읽지 않으니, 손으로 고치는 실습은 그대로입니다.
```bash
make switch K=request-dto V=off    # mall-portal만 다시 띄웁니다(30초쯤)
make replay T=03               # 회원정보 수정으로 등급·포인트가 다시 바뀌고(레드)
make switch K=request-dto V=on
make replay T=03               # 다시 무시됩니다(그린)
```
지금 값은 `make switch`(목록)나 `make lab`(랩 상황판 http://127.0.0.1:8099/lab)에서 봅니다. 끈 채로 두면 `make check`가 알림을 띄웁니다.
