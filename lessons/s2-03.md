# 2-3 관리자 기능이 열려 있다: 역할 검사 다시 짜기
⏱ 약 10분 · 고칠 파일 2개 · 바뀌는 줄 약 30줄

다온마켓은 고객센터용으로 회원 목록 화면(`/daon/customer/list`, 이름·전화·포인트)을 새로 만들었습니다. 슈퍼 관리자만 쓰라고 만든 기능입니다. 그런데 권한표(`ums_resource`)에 이 주소를 등록하지 않았고, 권한 검사는 「권한표에 없는 주소는 로그인만 했으면 통과」였습니다. 둘 다 [교육용 추가]입니다. 원본 mall의 권한 검사는 권한표에 없는 주소를 거부합니다.

| 계정(가짜) | 역할 | 비밀번호 |
|---|---|---|
| `admin` | 슈퍼 관리자(원본 데모 계정) | `macro123` |
| `staff_goods` | 상품 관리자 | `daon-pass-1!` |
| `staff_order` | 주문 관리자 | `daon-pass-1!` |

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=2-3
   make replay T=02
   make check L=2-3
   ```
   상품 담당 직원 `staff_goods`의 토큰으로 고객 목록을 부르면 회원 이름과 전화번호가 그대로 나옵니다.
2. **기본 거부로 바꿉니다.** `spring/mall-security/.../component/DynamicAuthorizationManager.java`에서 ✏️ 2-3 표시를 찾습니다.
   ```java
   if (needAuthorities.isEmpty()) {
       return new AuthorizationDecision(false);
   }
   ```
   - 권한표에 없는 주소는 누구에게도 열지 않습니다. 슈퍼 관리자도 마찬가지입니다.
   - 새 기능을 만들 때마다 권한을 정하지 않으면 그 기능은 아예 열리지 않습니다. 잊어도 닫혀 있는 쪽이 안전합니다.
   - 쓰지 않게 된 `AnonymousAuthenticationToken` import는 지웁니다.
3. **새 기능을 권한표에 올립니다.** 2번만 하면 슈퍼 관리자도 고객 목록을 못 봅니다(정상 요청 시험이 레드). `spring/mall-admin/.../config/MallSecurityConfig.java`의 ✏️ 2-3 표시에서 고객 목록을 관리자 계정 관리(`/admin/**`)와 같은 권한에 묶습니다.
   ```java
   ConfigAttribute adminOnly = map.get("/admin/**");
   if (adminOnly != null) {
       map.put("/daon/customer/**", adminOnly);
   }
   ```
   - 운영에서는 관리자 화면의 [권한 → 리소스 관리]에 새 리소스를 등록하고 역할에 연결합니다. 랩은 DB를 다시 만들지 않으려고 코드로 넣습니다.
   - `/admin/**` 권한이 없으면(`adminOnly == null`) 아무것도 넣지 않습니다. 그러면 2번 규칙에 따라 닫힌 채로 남습니다.
4. **⑤ 탐지: 거부를 로그로 남깁니다.** 같은 파일(`DynamicAuthorizationManager`)에서 거부하는 두 곳(권한표에 없는 주소, 역할에 없는 권한)에 보안 이벤트를 남깁니다.
   ```java
   SecurityEventLogger.denied("access.denied.no_permission", "2-3")
           .actor("admin:" + auth.getName())
           .target("path:" + path)
           .reason("권한표에 없는 주소(기본 거부)")
           .request(request)
           .log();
   ```
   - 로그인하지 않은 요청은 남기지 않습니다(401로 따로 끝납니다). 로그인한 직원이 자기 권한 밖 기능을 부르는 것이 의심 신호입니다.
   - 같은 직원의 `count`가 짧은 시간에 늘면 권한 밖 메뉴를 하나씩 눌러 보고 있다는 뜻입니다.
5. **확인합니다.**
   ```bash
   make check L=2-3      # 권한별 호출 행렬
   make replay T=02      # [그린] 막힘
   make logs S=mall-admin | grep access.denied.no_permission
   ```
   | 호출 | admin | staff_goods | staff_order |
   |---|---|---|---|
   | `GET /daon/customer/list` | 200 | 403 | 403 |
   | `GET /product/list` | 200 | 200 | — |
   | `GET /order/list` | 200 | — | 200 |

## Express라면
`diffs/s2-03/express.diff`. EverShop은 관리자 계정의 역할이 비어 있으면 `'*'`(전부 허용)로 봅니다. 같은 기본 거부로 바꾸고, 권한 없음은 401이 아니라 403으로 답합니다. 보안 이벤트 도우미는 `diffs/common/express-security-event.diff`를 먼저 넣습니다.

## 참고: 메서드 보안
URL 규칙 대신 `@EnableMethodSecurity` + `@PreAuthorize`로 컨트롤러 메서드마다 역할을 적는 방법도 있습니다. 어느 쪽이든 핵심은 같습니다. 정하지 않은 것은 닫혀 있어야 합니다.

## 선택: 끄면 레드, 켜면 그린(영상용 방어 스위치)
완료 지점(`make goto L=2-3 AT=done`, 또는 그 뒤 수업)의 정답 코드는 `secure-kit.admin-default-deny.enabled` 스위치를 읽습니다. 코드를 고치지 않고 보호를 껐다 켤 수 있습니다. 시작 지점 코드는 스위치를 읽지 않으니, 손으로 고치는 실습은 그대로입니다.
```bash
make switch K=admin-default-deny V=off    # mall-admin만 다시 띄웁니다(30초쯤)
make replay T=02               # staff_goods가 고객 목록을 다시 보고(레드)
make switch K=admin-default-deny V=on
make replay T=02               # 다시 막힙니다(그린)
```
지금 값은 `make switch`(목록)나 `make lab`(랩 상황판 http://127.0.0.1:8099/lab)에서 봅니다. 끈 채로 두면 `make check`가 알림을 띄웁니다.
