# 6-4 비밀번호 없이 열린 Redis·MongoDB·RabbitMQ·MinIO
⏱ 약 10분 · 고칠 파일 자바·설정 10여 개 + 새 파일 6개 · 아키텍처 A1(`infra/compose.a01.yml`, `infra/gateway/`)

> 이 랩이 만든 범위: 망 넷(edge·app·data·admin)과 data 망 internal, 저장소 포트 닫기, MongoDB·RabbitMQ·MinIO 인증과 기본 계정 교체, 게이트웨이(파일 주소 9000·관리자 입구 8443·접근 로그 trace_id), 앱이 받는 비밀은 OpenBao KV, 믿는 프록시만 X-Forwarded-For(E09), Redis 권한 캐시 서명(F25). 앱 API·고객 웹 등 나머지 포트를 모두 게이트웨이 뒤로 옮기는 일(app 망 internal)은 아직 없습니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=6-4
   make replay T=16      # PC에서 포트가 열려 있고, 안쪽도 MongoDB 인증 없음·RabbitMQ 기본 계정·MinIO 루트 기본값
   make check L=6-4
   ```
2. **망을 나누고 포트를 닫습니다(✏️ `compose.a01.yml`).** `infra/arch.txt`의 `a01` 줄이 켜져 있으면 망이 `edge`(게이트웨이만)·`app`(앱·고객 웹·가짜 외부 서비스·이그레스)·`data`(저장소·OpenBao, `internal: true`)·`admin`(관리자 앱·관리 화면)으로 나뉩니다. 저장소의 `ports:`는 지웁니다. 상품 사진 주소(9000)는 게이트웨이가 받아 버킷 `mall`의 읽기(GET·HEAD)만 MinIO로 넘기고 나머지는 404·403입니다.
3. **MongoDB에 인증을 켭니다(✏️ `infra/mongo/entrypoint.sh`).** 기존 볼륨에도 같게 동작하도록 컨테이너 안에서만 잠깐 서버를 띄워 계정(앱 `daon-portal`: mall-port 읽기·쓰기만, 랩 도구 `lab-ops`)을 맞춘 뒤 `--auth` 서버로 바꿉니다.
4. **RabbitMQ 기본 계정을 지웁니다(✏️ `infra/rabbitmq/entrypoint.sh`).** 기존 볼륨에서는 `RABBITMQ_DEFAULT_USER`가 먹지 않으므로 서버가 뜬 직후 `rabbitmqctl`로 맞춥니다. **앱 계정을 먼저 만들고 그다음 `guest`·`mall`을 지웁니다.** 앱 계정은 태그가 없고 `/mall`에서만 권한이 있습니다. 관리 화면은 관리자 입구의 `/rabbitmq/`로만 엽니다.
5. **MinIO 루트를 바꾸고 앱 전용 키를 둡니다(✏️ `compose.a01.yml`, `infra/minio/init.sh`).** 루트 계정은 `.env`의 값으로 교체합니다(콘솔 9001은 PC에 열지 않음). 앱은 버킷 `mall`의 목록·읽기·쓰기·삭제만 되는 접근 키를 씁니다.
6. **앱이 받는 비밀은 시크릿 저장소에서 받습니다(✏️ `openbao/init.sh`, `DaonVaultPostProcessor`, `application-*.yml`, `compose.yml`).** portal은 `mongo_password`·`rabbit_password`, admin은 `minio_access_key`·`minio_secret_key`를 KV(`secret/daon/<앱>`)에서 받습니다. 환경 변수로는 받지 않습니다. `StartupSecretCheck` 점검 목록에 이 칸들을 더했고, `infra/secrets/rotation-list.yaml`의 `rabbitmq-app`·`minio-root`를 `rotated`로 바꿉니다. → `make replay T=15` 그린.
7. **IP는 믿는 프록시만 믿습니다(✏️ 새 파일 `ClientIp`, `RequestUtil`, `LoginRateLimiter` 등).** 소켓 주소가 `DAON_TRUSTED_PROXIES`(게이트웨이·고객 웹)일 때만 그 프록시가 넣은 `X-Forwarded-For`의 **마지막 값**을 씁니다. PC에서 앱으로 바로 보낸 헤더는 무시합니다.
8. **권한 캐시를 믿지 않습니다(✏️ `UmsAdminCacheServiceImpl`).** 권한 목록을 Redis에 쓸 때 서명(HMAC, 키는 OpenBao `secret/daon/cache-hmac`)을 옆 키(`…:sig`)에 쓰고, 읽을 때 맞지 않거나 없으면 버리고 DB에서 다시 읽습니다. 이때 `cache.integrity.failed`를 남깁니다.
9. **확인합니다.** `make replay T=16`·`T=15` 그린, `make check L=6-4`. 캐시 시험은 로그인한 직원의 정확한 키에서 서명 손상과 본문 변경을 따로 검사합니다. 금지된 주문 권한 추가는 거부되고 원래 상품 권한은 유지돼야 합니다. 원문·서명·남은 TTL은 예외에도 복구합니다. 계정 값은 출력하지 않습니다.
10. **스위치.** `make switch K=cache-hmac V=off`(서명 확인 끔), `make switch K=ip-trust V=off`(X-Forwarded-For를 쓰지 않고 늘 소켓 주소). 망 분리·계정 교체는 끌 수 없습니다.

## 막힐 때
- DB 관리 도구가 붙지 않습니다: 컨테이너 안에서 엽니다. `docker exec -it daon-mysql-1 mysql -uroot -p`
- RabbitMQ 계정을 바꾸기 전에 앱 계정을 먼저 만들지 않으면 앱이 큐에 못 붙습니다. 준비 스크립트에 순서가 고정돼 있습니다.
- 앱 계정 비밀번호(`.env`)를 바꾸면 `make up`으로 준비 컨테이너와 `openbao-init`을 다시 돌리고 **앱을 다시 띄웁니다**(앱은 시작할 때 한 번 받습니다).
- 8443이 이미 쓰이고 있으면 `infra/.env`의 `DAON_GATEWAY_ADMIN_PORT`를 바꿉니다.
- 서명 없는 옛 캐시 값이 남아 있으면 처음 한 번 `cache.integrity.failed`가 찍힙니다. 전환 때는 캐시를 비웁니다.
- `data` 망은 `internal`이라 그 안의 컨테이너는 바깥으로 못 나갑니다. 이미지·의존성 내려받기는 `make up`의 빌드 단계에서 끝납니다.

## 남는 이벤트
`cache.integrity.failed`(WARN). 새 이벤트는 없습니다. 저장소 쪽 신호(Redis `ACL LOG`, MongoDB·RabbitMQ 인증 실패 로그)와 게이트웨이 접근 로그(`make logs S=gateway`, `trace_id`)는 8-4에서 모읍니다.
