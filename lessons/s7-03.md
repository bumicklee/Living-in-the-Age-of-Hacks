# 7-3 포크의 숙명: 원본 보안 패치를 72시간 안에
⏱ 약 8분 · 고칠 파일 `spring/pom.xml`(충돌 한 번) + `spring/UPSTREAM.md` · 코드 수업이 아니라 절차 수업

포크한 순간부터 원본의 보안 패치는 저절로 오지 않습니다. 누군가 지켜보고, 골라 들여오고, 걸린 시간을 적어야 합니다. 72시간은 법정 기준이 아니라 이 강의가 정한 운영 목표입니다.

## 따라 하기
1. **시간이 흐르는 것부터 봅니다.**
   ```bash
   make goto L=7-3
   make upstream-sim                              # .daon/upstream.git 에 가짜 원본과 보안 패치 커밋 하나(의존성 한 줄 올림)
   make upstream-status                           # 반영 안 됨, 공개 뒤 0시간
   DAON_FAKE_NOW=+74h make upstream-status        # 시계를 74시간 뒤로: 72시간 초과 (WARN 이벤트가 남음)
   make check L=7-3
   ```
2. **연습용 사본에서 가짜 원본을 추적합니다.** 랩 저장소에 연습 커밋을 남기지 않습니다.
   ```bash
   L=$PWD; W=.daon/practice-7-3
   rm -rf "$W" && mkdir -p "$W/spring" && cp spring/pom.xml "$W/spring/" && cd "$W"
   git init -q -b main
   git config user.name daon-lab && git config user.email lab@daon.example
   git add -A && git commit -qm "7-3 시작 지점의 pom.xml"
   git remote add upstream "$L/.daon/upstream.git"
   git fetch upstream
   ```
3. **사본에서 보안 패치 커밋만 골라 들여옵니다.** 이 패치는 7-2에서 SBOM 설정을 더한 `pom.xml` 줄 바로 옆을 고쳐서 **충돌이 한 번** 납니다.
   ```bash
   git cherry-pick -x upstream/main
   # 충돌: pom.xml에서 표시를 지우고 3.21.0과 7-2의 SBOM 줄을 함께 남깁니다.
   git add spring/pom.xml
   git -c core.editor=true cherry-pick --continue
   cd "$L" && cp "$W/spring/pom.xml" spring/pom.xml
   ```
4. **반영 기록을 남깁니다(✏️ `spring/UPSTREAM.md`).** 「원본 보안 패치 반영 기록」 표를 만들고 한 줄을 더합니다: 원본 커밋(앞 12자) · 공개 시각 · 반영 시각 · 걸린 시간 · 충돌.
5. **확인합니다.** `make upstream-status` → 「반영됨, 걸린 시간 N시간」. `make check L=7-3` 6개 통과.

## 충돌을 줄이는 방법
우리 수정을 원본 파일 안에 두지 말고 옆 파일(`daon/` 패키지, `mall-security`의 새 클래스)에 둡니다. 섹션 2부터 다온 코드를 따로 둔 이유입니다.

## 막힐 때
- 충돌이 나자 `--abort`로 되돌렸다면 처음부터 다시: 상태 보기 → 파일 열기 → 표시 지우기 → `add` → `continue`.
- 다음 수업에서 시간이 이상하면 `DAON_FAKE_NOW`가 켜진 채인지 확인합니다(`echo $DAON_FAKE_NOW`, 지우려면 `unset DAON_FAKE_NOW`).
- 원본이 「보안 패치」라고 표시하지 않으면: 원본의 보안 공지·릴리스 노트·권고 목록을 구독해서 알아냅니다(수업 노트).
- Express: `diffs/s7-03/express.diff`는 `express/UPSTREAM.md`에 같은 칸의 표를 만듭니다(EverShop은 GPL-3.0이라 포크 소스 전체를 공개).
