# 10-5 원장 대사: 숫자가 맞는지 매일 확인
⏱ 약 8분 · 고칠 파일 자바 2개(포털 포인트 원장, 관리자 권한표) + 새 파일 3개(관리자 대사 작업·API·예약 설정) · A5 경보 사용 · 방어 스위치 `reconcile`

## 따라 하기
1. **어긋난 숫자를 만듭니다.**
   ```bash
   make goto L=10-5
   make ledger-break M=101          # 원장 없이 alice 포인트만 +500 (랩 도구)
   docker exec daon-mysql-1 mysql -uroot -proot mall -e "SELECT integration FROM ums_member WHERE id=101; SELECT SUM(IF(change_type=0,change_count,-change_count)) FROM ums_integration_change_history WHERE member_id=101;"
   make reconcile                   # 대사 API가 없다 [레드]
   make check L=10-5
   ```
   10-1 재연을 돌린 뒤라면 그것이 만든 진짜 불일치도 보입니다(원본은 주문에 포인트를 써도 원장을 남기지 않습니다).
2. **원장을 남기는 길부터 고칩니다(✏️ `OmsPortalOrderServiceImpl`, `DaonMoneyDao`).** 포인트를 쓰거나(`change_type 1`) 취소로 돌려줄 때(`0`) 잔액 UPDATE와 같은 트랜잭션에서 `ums_integration_change_history`에 한 줄. 남기지 않는 경로가 있으면 대사가 매일 불일치를 냅니다.
3. **대사 작업(새 ✏️ `mall-admin/.../daon/DaonReconcileJob.java`·`DaonReconcileController.java`·`DaonSchedulingConfig.java`, ✏️ `config/MallSecurityConfig.java`).**
   - 매일 04:00(`@Scheduled`) + 관리자 전용 `POST /daon/reconcile/run`(권한표에 `/daon/reconcile/**`를 관리자 계정 관리와 같은 권한으로).
   - 기준 시각 하나를 정하고 그 시각까지만 셉니다.
   - 대사 1: 회원 잔액 ↔ 원장 합계(더함 − 뺌). 쿼리 하나로 다른 회원만.
   - 대사 2: 앱이 만든 결제 완료 주문(9301~) ↔ `oms_payment_event`의 승인 기록(10-4) 금액. 고객이 부른 「결제 성공」으로 완료된 주문이 여기서 걸립니다.
   - 결과는 `oms_reconcile_result`(불일치 회원·주문 ID만). 불일치 하나에 `ledger.mismatch` 한 줄, 50줄 넘으면 요약 한 줄.
4. **확인합니다.**
   ```bash
   make up STACK=spring
   make reconcile                   # member:101(그리고 앞 재연의 흔적)
   make ledger-fix M=101 && make reconcile
   make check L=10-5                # 5개(정상 1개 포함)
   ```
   Grafana 경보 「`ledger.mismatch` 한 번이라도」 → Mailpit(127.0.0.1:8025) 알림 메일.
5. **스위치.** `make switch K=reconcile V=off` → `make reconcile`이 아무것도 알리지 않고, 주문 포인트가 원장에 남지 않음 → `V=on`.

## 막힐 때
- 시드 상태인데 불일치가 많다: 앞 수업 재연·시험이 포인트를 바꿨습니다. 회원 포인트를 원장 값으로 **덮어쓰지 마세요.** 어느 쪽이 맞는지 원인을 먼저 찾습니다. 랩에서는 `make money-reset`(원장 맞춤 줄을 함께 남김) 또는 `make wipe`.
- 원본 데모 회원(100번 아래)은 원장이 처음부터 없어 대사에서 뺐습니다.
- 대사가 돌 때 주문이 계속 들어오면 경계 시각에서 어긋납니다. 기준 시각까지만 셉니다.
- Express: 같은 대사 SQL을 PostgreSQL 문법으로 옮기는 것은 이 수업의 숙제로 둡니다(EverShop에는 포인트가 없어 고객 `meta_data.points`).

## 남는 이벤트
`ledger.mismatch`(WARN, mall-admin, actor `system:reconcile`, target `member:<ID>`·`order:<ID>`, reason 「포인트와 원장 합계 불일치」·「결제 완료 주문에 결제사 승인 기록이 없거나 금액이 다름」). 대사는 사후 확인입니다. 실시간 차단은 10-2·10-4가 맡습니다.
