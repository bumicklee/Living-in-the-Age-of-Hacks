# 5-2 데모 기본 JWT 키를 운영에서 바꾸기: 비대칭 서명과 회전
⏱ 약 12분 · 고칠 파일 4개 + 새 파일 3개 · 아키텍처 A4(OpenBao)

이 수업은 공격을 재연하지 않습니다. 방어 코드를 넣고, 방어가 동작하는지 시험으로 확인합니다.

## 따라 하기
1. **시작 지점으로 갑니다.** `make goto L=5-2` 토큰 머리글이 `HS256`이고 설정 파일에 서명 값(`jwt.secret`)이 있습니다.
2. **서버가 검증 방식을 정합니다.** `mall-security/.../util/JwtTokenUtil.java`의 `getPayloadFromToken`을 `JwtSigner.verify`로 바꿉니다(ES256 하나만 받고, `kid`·`iss`·`aud`를 확인). `exp`가 없는 토큰은 만료로 봅니다(`isTokenExpired`).
3. **서명을 금고에 맡깁니다.** 새 파일 `mall-security/.../token/JwtSigner.java`: OpenBao transit `daon-jwt`에 서명을 요청하고(`marshaling_algorithm=jws`), 공개키는 한 번 받아 두었다가 10초마다 다시 읽습니다. 금고가 안 닿으면 로그인을 막습니다.
4. **설정을 고칩니다.** 두 앱 `application.yml`에서 `jwt.secret` 줄을 지우고 `daon.jwt.audience`(`daon-portal`/`daon-admin`)를 둡니다. 회원 앱에 `/.well-known/jwks.json`(`DaonJwksController`)을 열어 둡니다(`secure.ignored.urls`).
5. **확인합니다.**
   ```bash
   make unit-test                          # JwtAlgorithmPinTest 6개
   make check L=5-2
   make rotate-key K=jwt ACTION=rotate     # 새 키 버전(겹침 시작)
   make rotate-key K=jwt ACTION=retire     # 옛 버전 폐기
   make rotate-key K=jwt ACTION=reset      # 폐기 해제(랩을 되돌릴 때)
   ```
   회전 직후에는 옛 토큰도 200, 폐기하면 옛 토큰만 401입니다. 앱이 키 목록을 다시 읽는 간격(10초) 뒤에 반영됩니다.
6. **스위치.** `make switch K=jwt-hardening V=off`는 `exp` 필수와 `iss`·`aud` 확인만 끕니다. 서명을 금고로 옮긴 부분은 끌 수 없습니다.

## 남는 이벤트
`auth.token.denied_alg` · `denied_unknown_kid` · `denied_retired_key` · `denied_no_exp` (토큰 원문은 남기지 않음)

## 미션 아님 · 안 하는 것
옛 기본 비밀값으로 토큰을 만들어 보내는 재연은 이 랩에 없습니다.
