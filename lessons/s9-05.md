# 9-5 백오프·지터·재시도 예산·서킷 브레이커
⏱ 약 9분 · 고칠 파일 자바 2개(`DaonPaymentClient`·`DaonPayRequestReceiver`)·pom 1개 + 새 파일 1개(`RetryBudget`) · **아키텍처 A6**(`infra/compose.a06.yml`, RabbitMQ 재시도 큐·DLQ, 새 컨테이너 없음) · 방어 스위치 `resilience`

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=9-5 && make up STACK=spring
   make measure M=retry          # 9-4와 같은 증폭 [레드]
   make check L=9-5
   ```
2. **재시도는 한 곳으로(✏️ `DaonPaymentClient.java`).** 안에서 바로 다시 하던 3번을 지우고 한 번만 부릅니다. 재시도는 큐 소비자 한 곳에서만 합니다.
3. **A6를 켭니다(✏️ `infra/arch.txt`에 `a06`, 새 `infra/compose.a06.yml`·`infra/rabbitmq/a06-definitions.json`·`a06.conf`).** RabbitMQ가 뜰 때 정의 파일을 읽어 만듭니다.
   - `daon.pay.retry`: 메시지마다 expiration이 지나면 `daon.pay.request`로 돌아오는 재시도 큐
   - `daon.pay.dlx` → `daon.pay.dlq`: 끝내 실패한 결제 요청이 쌓이는 곳, 정책 `daon-pay-dlx`가 `daon.pay.request`의 거절 메시지를 보냄
   - 큐 구조는 앱이 아니라 RabbitMQ 쪽(운영 설정)에 둡니다. 앱은 보내기만 합니다.
4. **소비자(✏️ `DaonPayRequestReceiver.java`, 새 `RetryBudget.java`).** 실패하면 ① 재시도 3번을 넘었으면 DLQ ② 재시도 예산(최근 1분 새 요청의 10%, 최소 3번)이 바닥나면 DLQ ③ 아니면 재시도 큐에 지연(1·2·4초 지수 백오프, 절반은 무작위 지터)을 달아 보냅니다. 결제사의 거절(4xx)은 다시 보내지 않습니다. 메시지 헤더 `X-Trace-Id`는 그대로 따라갑니다.
5. **서킷 브레이커(✏️ `DaonPaymentClient.java`, pom에 `io.github.resilience4j:resilience4j-circuitbreaker:2.2.0`).** 최근 10번 중(최소 4번) 실패가 50% 이상이면 20초 동안 결제사를 부르지 않습니다. 20초 뒤 시험 호출 1번이 성공하면 닫힙니다. 4xx는 실패로 세지 않습니다. 열린 동안에도 결제 요청은 202 「결제 대기」로 받습니다(주문은 받고 결제는 나중에, 14-3).
6. **확인합니다.**
   ```bash
   make up STACK=spring           # A6: RabbitMQ를 다시 띄워 정의 파일을 읽는다
   make measure M=retry           # 기준(1.2배) 이하 [그린]. 9-4 표와 나란히
   make check L=9-5               # 5개(정상 2개 포함), 측정 한 번 약 75초
   docker exec daon-rabbitmq-1 rabbitmqctl -q list_queues -p /mall name messages
   ```
   관리 화면 http://127.0.0.1:8443/rabbitmq/ (daon-ops, `infra/.env`)에서 `daon.pay.dlq` 메시지의 `X-Trace-Id` 헤더를 보고, 그 번호로 Grafana에서 결제 요청 줄을 찾습니다.
7. **스위치.** `make switch K=resilience V=off` → `make check L=9-5` 레드 → `V=on`.

## 막힐 때
- 재시도를 클라이언트와 큐 양쪽에 남겨 두었다: 「재시도는 한 곳」부터 봅니다.
- 메시지가 사라진다: 재시도 큐의 DLX 이름·라우팅 키가 틀렸습니다. 관리 화면의 바인딩을 봅니다.
- `PRECONDITION_FAILED`(큐 인자 다름): 앱이 `daon.pay.retry`·`daon.pay.dlq`를 다른 인자로 선언하면 RabbitMQ가 거절합니다. 앱은 `daon.pay.request`만 선언합니다.
- 메시지마다 expiration을 단 재시도 큐는 맨 앞 메시지가 만료돼야 뒤 메시지가 나옵니다(4초짜리 뒤의 1초짜리는 4초 기다림). 지연 단계가 많으면 단계별 큐를 둡니다.
- Express: `diffs/s9-05/express.diff`는 다온 확장의 결제 스텁 호출에 서킷 브레이커(작은 상태 기계)·지수 백오프·지터를 붙이고, 실패 횟수를 넘은 `event` 표 줄을 「죽은 이벤트」로 옮기는 diff입니다.

## 남는 이벤트
`resilience.circuit.opened`(WARN)·`resilience.circuit.closed`(INFO)·`resilience.retry_budget.exhausted`(WARN)·`queue.dead_lettered`(WARN). 공격이 아니라 장애 신호일 때가 많지만 같은 형식으로 남겨, 보안 이벤트와 같은 시각에 몰리는지 봅니다.
