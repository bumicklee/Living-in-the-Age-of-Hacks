# 13-5 AI를 쓰는 공격자와 가짜 채용
⏱ 약 7분 · 사고 수업(고치기 없음, `make check` 없음) · 아키텍처 변화 없음 · 재연 T35(13-6에서)

AI가 바꾼 것은 「찾는 속도」입니다. 공격자는 관리가 소홀한 **외곽 시스템**과 **개발자 노트북**을 먼저 찾습니다. 그래서 탐지(8장)와 접근 축소(13-6)가 같이 가야 합니다.

> 금융권 연쇄 사고는 수사 중이라 사실관계가 바뀔 수 있습니다. 기관 이름과 기준일을 붙여 말합니다. 개인 신원·도구 이름·사용법은 다루지 않습니다. 랩 밖 시스템에는 아무것도 하지 않습니다(README 3절 안전 기준).

## 따라 하기
1. **노린 곳의 공통점을 봅니다(영상의 그림).** 대출모집인 조회 서비스·영업지원 시스템 같은 외곽 시스템. 보도된 원인 네 가지: 자산 목록 누락, 인증 없는 조회, 방치된 취약점·지원 끝난 버전, 늦은 탐지.
2. **가짜 채용 → 노트북 → 운영 접근.** 가짜 채용 PDF·채용 시험 코드가 개발자 노트북에서 실행되면, 그 노트북이 가진 운영 접근이 첫 단추가 됩니다.
3. **다온마켓의 「개발자 노트북 체크리스트」를 만듭니다.** 운영 DB 접속 정보 · 관리자 웹 로그인 세션 · Gitea 토큰(A8) · OpenBao 토큰(A4) · 공용 운영 계정 비밀번호.
   ```bash
   make goto L=13-5
   make up STACK=spring
   make replay T=35        # 공용 계정 daon_ops·데모 계정 macro 로그인, 상시 슈퍼 권한 [레드] — 13-6에서 고칩니다
   ```
4. **두 규칙을 적어 둡니다.** 「채용 과제·외부 코드는 운영 자격증명이 없는 격리 환경에서 연다」 · 「운영 접근은 개인 계정 + 필요할 때만 + 기록」.

## 막힐 때
- 「AI 공격 도구를 써 보고 싶다」: 이 강의 범위가 아닙니다.
- 숫자가 출처마다 다르다: 자막에 기관 이름을 붙이고 기준일(2026-10 말)을 밝힙니다.

## 확인 문제
1. 사건들이 노린 곳의 공통점은? (핵심망보다 관리가 소홀한 외곽 시스템. 자산 목록에서 빠지거나 인증 없이 조회되는 곳.)
2. 채용 과제 코드를 열 때 지킬 규칙 하나는? (운영 자격증명이 없는 격리 환경(별도 VM·컨테이너)에서 연다.)
