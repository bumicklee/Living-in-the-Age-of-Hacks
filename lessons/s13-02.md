# 13-2 바이비트·업비트와 코인 해킹 12년, 세탁과 동결
⏱ 약 8분 · 사고 수업(고치기 없음, `make check` 없음) · 아키텍처 변화 없음

공격자가 노린 곳은 12년 동안 **핫월릿 → 브리지·검증자 → 서명 경로**로, 점점 사람 쪽으로 옮겨 왔습니다. 동결·회수는 「탐지 속도」의 문제입니다. 먼저 알아챈 쪽이 더 많이 지킵니다.

> 숫자·날짜는 출처를 붙여 말하고, 회사 발표 범위를 넘어 원인을 단정하지 않습니다(예: 업비트 2025는 「확인되지 않았다」). 세탁 경로·도구 이름은 다루지 않습니다.

## 따라 하기
1. **세 시대만 고릅니다(영상의 연표).** 핫월릿 시대(마운트곡스·코인체크·업비트 2019) · 브리지·검증자 시대(로닌) · 서명 경로 시대(바이비트·업비트 2025·바이낸스).
2. **「블라인드 서명」을 정의합니다.** 서명하는 사람이 실제로 서명되는 내용을 직접 확인하지 못한 채 하는 서명. 바이비트: 서명 화면이 바뀌어 서명자가 실제 내용을 모른 채 서명했다(조사 회사 중간 보고 기준).
3. **다온마켓의 블라인드 승인 세 곳을 짚습니다.**
   - 관리자 웹 반품 승인: 화면에 보이는 금액과 서버가 받는 금액이 다를 수 있다(요청 본문이 금액을 정한다).
     ```bash
     make goto L=13-2
     make up STACK=spring
     ```
     관리자 웹(http://127.0.0.1:8090) → 주문 → 반품 신청 처리 대화 상자를 열고, 브라우저 개발자 도구에서 요청 본문의 `returnAmount`·`handleMan`을 봅니다(값은 시드의 가짜 값).
   - 정산 계좌 변경 직후의 정산 승인(13-4의 「대상 계좌 규칙」).
   - 권한 부여 승인(13-6).
4. **「동결」을 다온마켓에서는 「실행 전 취소」로 바꿔 생각합니다.** 13-4의 지연 실행 + 취소 창 그림을 예고합니다.

- 「업비트는 개인키가 털린 것 아니냐」: 회사 발표 범위만 말합니다.
