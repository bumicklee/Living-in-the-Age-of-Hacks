# 3-6 파일 업로드: 확장자·내용·저장 위치
⏱ 약 10분 · 고칠 파일 5개 + 새 파일 1개 · 바뀌는 줄 약 190줄(새 검사기 104줄 포함)

상품 사진을 올리는 원본 기능(`POST /minio/upload`)을 그대로 씁니다([교육용 추가] 없음). 데모 화이트리스트가 그대로 남은 흔한 모습입니다.

## 따라 하기
1. **레드인 것부터 봅니다.**
   ```bash
   make goto L=3-6
   make replay T=08
   make check L=3-6
   ```
   | 바꾸는 것 | 보이는 것 |
   |---|---|
   | ① 로그인 없이 업로드 | `HTTP 200 code=200`, 받아진다 |
   | ② 그림이 아닌 글자 파일을 `.png`·`image/png`라고 적어 올림 | 그대로 저장되고 공개 주소(127.0.0.1:9000/mall/…)로 열린다. 저장 이름이 올린 이름 그대로 |
   | ③ 같은 이름으로 한 번 더 | 앞 파일이 바뀐다(덮어쓰기) |
   | ④ 로그인 없이 버킷 목록 `http://127.0.0.1:9000/mall/` | `HTTP 200`, 객체 이름이 모두 보인다 |
2. **인증을 붙입니다.** `spring/mall-admin/src/main/resources/application.yml`의 ✏️ 3-6 표시에서 `/minio/upload`·`/aliyun/oss/policy` 두 줄을 지웁니다. 같은 파일의 멀티파트 상한도 줄입니다(`max-file-size: 5MB`).
   - 그러면 2-3의 기본 거부와 권한표가 적용됩니다. 업로드(`/minio/**`)는 상품 관리 권한과 같게 올려 두었습니다(`MallSecurityConfig`). 상품 담당·슈퍼 관리자만 올립니다.
   - 로그인 없는 요청은 `HTTP 200`에 본문 `code=401`로 돌아옵니다(mall의 응답 모양).
3. **관리자 화면 업로드 부품이 토큰을 싣게 합니다.** 원본 업로드 부품은 토큰을 싣지 않습니다(주소가 열려 있어서 동작했다). `spring/mall-admin-web/src/components/Upload/singleUpload.vue`·`multiUpload.vue`의 ✏️ 3-6 표시.
   ```ts
   const userStore = useUserStore()
   const uploadHeaders = computed(() => ({ Authorization: userStore.userInfo.token }))
   ```
   ```vue
   :headers="useOss ? undefined : uploadHeaders"
   ```
4. **업로드 검사기를 씁니다.** `spring/mall-admin/.../daon/UploadValidator.java`(새 파일)와 `MinioController.java`의 ✏️ 3-6 표시.
   ```java
   UploadValidator.ImageType type = UploadValidator.check(file);   // 크기(2MB) → 앞 16바이트 서명(PNG·JPEG·GIF·WebP만)
   String objectName = UploadValidator.objectName(type);            // 20261108/<무작위 UUID>.png
   // putObject(...).object(objectName).contentType(type.mimeType)
   ```
   - 거절은 `ResponseEntity`로 상태를 맞춥니다: 내용이 그림이 아니면 400, 크기 초과는 413.
   - 클라이언트가 보낸 Content-Type과 파일 이름은 쓰지 않습니다. 원래 이름은 응답의 표시용(`name`)으로만.
   - SVG·HTML은 받지 않습니다. 둘 다 브라우저에서 스크립트를 실행할 수 있습니다.
5. **버킷 목록을 닫습니다.** `infra/minio/init.sh`의 ✏️ 3-6 표시. `mc anonymous set download`는 객체 읽기와 함께 목록까지 엽니다. 객체 읽기(`s3:GetObject`, `mall/*`)만 여는 정책으로 바꿉니다.
   ```sh
   cat > /tmp/mall-read-only.json <<'JSON'
   {"Version":"2012-10-17","Statement":[{"Effect":"Allow","Principal":{"AWS":["*"]},"Action":["s3:GetObject"],"Resource":["arn:aws:s3:::mall/*"]}]}
   JSON
   mc anonymous set-json /tmp/mall-read-only.json daon/mall
   ```
   상품 사진 주소는 그대로 열립니다. MinIO 관리 계정·포트는 6-4에서 고칩니다.
6. **⑤ 탐지.** 거절 지점에 남깁니다. 올린 사람이 정한 파일 이름은 넣지 않습니다(로그 위조 통로).
   ```java
   SecurityEventLogger.denied(r.event, "3-6")          // upload.rejected.type 또는 upload.rejected.size
           .actor("admin:" + auth.getName())
           .target("upload:-")
           .reason(r.reason)                            // 「내용이 허용 형식이 아님: 감지=text」
           .log();
   ```
7. **확인합니다.**
   ```bash
   make check L=3-6      # 앱 둘과 관리자 화면을 다시 빌드하고, minio-init이 새 정책을 겁니다
   make replay T=08      # [그린] 네 경우 모두 막힘
   make logs S=mall-admin | grep upload.rejected
   ```
   상품 담당 직원의 정상 그림 업로드(공개 주소로 보임)와 관리자 화면 브랜드 추가 화면의 로고 업로드 시험도 그린이어야 합니다.

## Express라면
`diffs/s3-06/express.diff`(먼저 `diffs/common/express-security-event.diff`). 형식을 파일 앞 바이트로 정하고 저장 확장자도 내용으로(`CustomMemoryStorage.js`, E13), 무작위 저장 이름(`generateFileName.js`, E14), media 경로는 그림 확장자만 내주기(`static.ts`, E13), 경로 검사에 구분자까지 비교(`validatePath.js`, E15).

## 선택: 끄면 레드, 켜면 그린(영상용 방어 스위치)
```bash
make switch K=upload V=off   # 검사기를 끈다(로그인·버킷 목록은 그대로)
make replay T=08             # ②③ 레드: 직원이 올린 글자 파일이 그대로 저장·덮어쓰기
make switch K=upload V=on
```
