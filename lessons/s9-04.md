# 9-4 내 재시도가 나를 공격한다: AWS·Cloudflare 장애
⏱ 약 7분 · 사고 수업(고치기 없음, `make check` 없음) · 아키텍처 변화 없음 · 재연 T24(측정만)

## 따라 하기
1. **시작 지점과 결제 요청 경로([교육용 추가]).**
   ```bash
   make goto L=9-4 && make up STACK=spring
   ```
   `POST /daon/order/{id}/pay` → 큐 `daon.pay.request`(202 「결제 대기」) → `DaonPayRequestReceiver` → `DaonPaymentClient` → 가짜 결제사(9101).
   - `DaonPaymentClient`: 시간 제한 1초, 실패하면 간격 없이 바로 다시(모두 3번).
   - `DaonPayRequestReceiver`: 실패하면 같은 큐 맨 뒤에 바로 다시 넣기(모두 3번). 두 계층이 곱해집니다.
2. **결제사를 늦춥니다.**
   ```bash
   make stub-fault S=pay MODE=slow MS=3000
   ```
3. **잽니다(약 75초).**
   ```bash
   make measure M=retry      # 결제 요청 10건(1초 간격) → 60초 동안 결제사가 받은 요청 수 = 증폭 배수 [레드]
   ```
   결제 요청 하나에 결제사 요청이 최대 9번(3 × 3). 5초 구간 막대에서 「느려질수록 요청이 는다」를 봅니다. 측정이 끝나면 스텁은 자동으로 정상(ok)입니다.
4. **원인 줄을 엽니다.** `DaonPaymentClient.pay()`의 `for` 세 번, `DaonPayRequestReceiver.handle()`의 「바로 다시 넣는다」.

## 막힐 때
- 배수가 PC마다 조금씩 다릅니다. 「모양」을 봅니다.
- 「재시도를 아예 없애면?」 재시도는 필요합니다. 상한·간격·예산이 없는 것이 문제입니다(9-5).
- 측정 중 Ctrl+C로 끊었다면 `make stub-fault S=pay MODE=ok`.

## 남는 이벤트
없음. 하위 서비스가 느려질 때 상위 요청 수가 오히려 늘면, 그것이 재시도 폭주의 신호입니다.
