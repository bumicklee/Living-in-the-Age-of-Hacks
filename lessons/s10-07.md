# 10-7 비용 고갈: LLM 키·SMS 펌핑·서버리스 청구서
⏱ 약 8분 · 고칠 파일 자바 1개(`UmsMemberController`) + 새 파일 1개(`DaonSmsBudget`) · 아키텍처 변화 없음(가짜 문자 `sms-stub` 127.0.0.1:9102) · 방어 스위치 `sms-budget`

## 따라 하기
1. **레드부터 봅니다.**
   ```bash
   make goto L=10-7
   make replay T=27 PART=sms     # 가짜 번호 010-0000-0001~0050 → 문자 50통, 국외 번호도 문자 사업자까지 [레드]
   curl -s 127.0.0.1:9102/_lab/stats
   make check L=10-7
   ```
   로그인 없이 부를 수 있는 인증 번호 요청 `GET /sso/getAuthCode`입니다. 요청 하나하나는 정상입니다.
2. **예산 세 겹(새 ✏️ `component/DaonSmsBudget.java`, ✏️ `UmsMemberController.getAuthCode`).** 문자 사업자를 **부르기 전에**.
   - 번호: 60초 1번(`SET NX EX 60`), 하루 5번 · IP: 10분 30번 · **전체: 한 시간 20건**(랩 값).
   - 전체 상한을 넘으면 `rl:sms:budget:tripped`를 그 시간이 끝날 때까지 두고 발송을 멈춥니다(503 「잠시 후 다시 시도」) + `budget.tripped.global` 한 번. 상한은 「사고를 멈추는 스위치」입니다. 걸리면 정상 사용자도 못 받으므로 사람이 봅니다.
   - 국가 제한: 국내 휴대전화 형식(`01X-XXXX-XXXX`)만. 그 밖은 400(문자 사업자를 부르지 않음). 가짜 문자 스텁은 원래 `010-0000-xxxx`만 받습니다.
   - Redis가 응답하지 않으면 보내지 않습니다(9-2).
3. **LLM·서버리스는 그림으로.** 사용자별 토큰 예산·제공사 지출 한도, 동시성 상한·예산 경보 자동 조치. 랩에는 LLM 스텁이 없습니다.
4. **확인합니다.**
   ```bash
   make up STACK=spring
   make replay T=27 PART=sms     # 20통에서 멈춤, 국외 번호는 앱이 400 [그린]
   make check L=10-7             # 4개(정상 1개 포함). 시험마다 카운터를 비운다
   ```
5. **스위치.** `make switch K=sms-budget V=off` → 레드 → `V=on`.

## 막힐 때
- 재연 직후 정상 인증 문자가 503: 전체 상한이 걸린 시간입니다. `make money-reset`(`rl:*` 비우기, 예산 포함).
- 계획의 IP 한도는 10/10분이었습니다. 재연이 한 IP(127.0.0.1)에서 오므로 IP 축이 먼저 막아 전체 상한이 보이지 않습니다. 랩은 30으로 두었습니다.
- Express: EverShop에는 문자 발송이 없습니다. `diffs/s10-07/express.diff`는 같은 예산을 비밀번호 재설정 메일 발송에 겁니다.

## 남는 이벤트
